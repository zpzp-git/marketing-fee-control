# 3.7.3 营销备用金模块实现说明

本文用于指导 Gemini 和 Codex 实现“营销备用金”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

营销备用金模块用于处理员工因营销事项产生的专项备用金借款、个人垫付报销、借款冲销/还款和备用金台账查询：

- 支持业务人员基于营销事项申请备用金，并模拟审批、付款和台账生成。
- 支持业务人员提交营销备用金报销单，录入费用、发票、营销事项和借款冲销信息。
- 支持无借款的个人垫付报销，以及有借款的报销冲销借款。
- 支持查看专项备用金台账中的借款总额、还款中金额、已还款金额、未还款金额和完结状态。
- 支持在 Demo 中模拟 OA 审批、金蝶付款申请、CBS 支付、凭证号回写、发票查验等外部动作。

Demo 阶段重点是跑通“备用金申请 -> 审批通过/模拟付款 -> 台账生成 -> 报销冲销 -> 台账金额更新”的闭环，不做真实付款、真实流程引擎和真实发票能力。

## 页面清单

| 页面 | Demo 定位 | 主要操作 |
|---|---|---|
| 营销备用金申请单 | 专项备用金借款申请单 | 新增、关联营销事项、多选预算信息、填写付款信息、保存草稿、提交审批、模拟付款、审批通过后生成专项备用金台账 |
| 营销备用金报销单 | 个人垫付/备用金报销核销单 | 新增、选择费用类型、关联营销事项、选择发票、冲销借款、提交审批、审批通过后更新预算/事项/发票/借款台账 |
| 专项备用金台账 | 备用金借款台账 | 查询、重置、汇总查询、导出模拟、查看详情、发起报销、发起还款 |
| 营销备用金还款申请 | 台账上的补充还款表单 | 选择借款台账、填写本次还款金额和账户信息、提交审批、审批通过后更新已还款金额 |

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 备用金借款闭环：营销备用金申请单 -> 选择未使用的营销事项 -> 填写本次借款金额和付款信息 -> 提交审批 -> 审批通过 -> 模拟金蝶/CBS 付款成功 -> 专项备用金台账新增借款记录，营销事项状态变为已使用，预算发生数更新。
2. 备用金报销冲销闭环：专项备用金台账 -> 选择未还清借款发起报销 -> 填写费用信息、发票信息和本次冲销金额 -> 提交审批 -> 审批通过 -> 借款台账已还款金额增加、未还款金额减少，营销事项费用台账新增费用记录。
3. 无借款个人垫付闭环：营销备用金报销单 -> 关联未使用营销事项 -> 填写费用明细和发票 -> 不选择借款或冲销金额为 0 -> 提交审批 -> 审批通过 -> 预算占用转发生，营销事项状态和费用台账更新；如报销合计大于冲销合计，则显示模拟付款信息。

还款申请作为补充闭环：从专项备用金台账选择未还款借款 -> 填写本次还款金额 -> 审批通过 -> 台账已还款金额增加、还款中金额清零、未还款金额减少；未还款金额为 0 时完结状态变为已完结。

## 主要字段建议

通用单据字段：

- 单据编号、单据名称、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 核算主体/核算公司、币种、凭证号、说明/借款说明、附件。
- 单据状态：草稿、审批中、已驳回、审批通过、付款中、已完成、付款失败。
- 审批信息：流程环节名称、审批人、审批日期、审批意见。

营销备用金申请单字段：

- 主表区：核算主体、币种、累计未还金额、本次借款合计、借款说明。
- 申请及借款信息：关联营销事项申请、营销活动计划分类、营销活动、预算科目、预算组织、申请可用金额、本次借款金额、借款类型。
- 付款信息：摘要、借款金额、收款方账号、付款方账号、建议支付日期、结算方式/付款方式、付款类型、支付方式、核算科目、实际支付日期。
- 关键规则：本次借款合计等于明细本次借款金额合计；建议支付日期默认申请日期后 1 天或按原设计可显示预计还款日期为申请日后 10 天；关联营销事项弹窗过滤创建人=申请人且事项状态=未使用。

营销备用金报销单字段：

- 主表区：核算主体、报销合计、累计未还金额、本次还款合计、凭证号、说明、价税合计金额、不含税金额、税额。
- 费用信息：费用类型、业务日期、金额、不含税金额、税额、预算扣减金额、费用小类名称、费用小类。
- 事项申请及预算信息：关联营销事项、营销活动计划分类、营销活动、预算科目、预算组织、申请可用金额、金额、最后一次报销、事项状态。
- 发票信息：发票号码、发票代码、发票类型、开票日期、价税合计金额、不含税金额、税额、可抵扣税额、转出税额、转出状态、发票主键。
- 备用金借款信息：借款单号、营销事项名称、营销活动、预算科目、预算部门、借款金额、已还金额、未还金额、本次冲销金额。
- 付款信息：摘要、付款金额、预计支付日期、付款方式、收款方账号、付款方账号、实际支付日期、付款类型、支付方式。
- 关键规则：报销合计等于费用信息金额合计；本次还款合计等于本次冲销金额合计；付款金额=报销合计-冲销合计，付款金额为 0 时付款区可隐藏或折叠。

营销备用金还款申请字段：

- 主表区：核算主体、累计未还金额、本次还款合计、币种、凭证号、说明。
- 借款信息：借款单号、借款金额、已还款金额、未还款金额、本次还款金额。
- 还款信息：还款方式、还款日期、还款账户名称及账号、还款金额。
- 关键规则：本次还款金额不能超过未还款金额；提交审批时增加还款中金额，审批通过后减少还款中金额并增加已还款金额。

专项备用金台账字段：

- 单据编号、单据名称、申请日期、申请部门、申请人、借款人、借款日期、预计还款日期。
- 借款总额、还款中金额、已还款金额、未还款金额、完结状态。
- 建议补齐：营销事项申请单号、营销事项名称、营销活动计划分类、营销活动、预算科目、预算部门、借款类型、核算主体、收款方账号、来源单据、付款状态、同步状态、失败原因。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `advanceApplications`：营销备用金申请单 8-12 条，状态覆盖草稿、审批中、已驳回、付款中、已完成、付款失败。
- `advanceReimbursements`：营销备用金报销单 8-12 条，覆盖无借款报销、部分冲销、全额冲销、需补付款、付款金额为 0。
- `advanceRepayments`：还款申请 5-8 条，覆盖审批中、已通过、已驳回。
- `advanceLedger`：专项备用金台账 10-15 条，覆盖未还款、部分还款、还款中、已完结、付款失败待处理。
- `marketingMatterOptions`：可关联营销事项 10-15 条，状态包含未使用、使用中、已使用；至少 3 条可被当前申请人选择。
- `invoiceOptions`：发票 mock 8-12 条，状态包含待查验、查验通过、查验失败、已报销、报销中。
- `paymentRecords`：模拟金蝶/CBS 付款记录，包含付款状态、支付方式、实际支付日期、失败原因。
- `budgetUsageRecords`：预算占用/发生 mock 记录，用于展示提交和审批通过后的金额变化。

样例数据要能串起来：

- 一条营销事项先通过备用金申请生成借款台账，再通过报销单冲销。
- 一条报销单不关联借款，展示个人垫付报销并生成付款金额。
- 一条报销金额小于借款余额，台账显示部分未还。
- 一条报销金额等于借款余额，台账完结状态变为已完结。
- 一条付款失败记录，显示失败原因和“模拟重试支付”入口。

## 关键交互

- 列表页统一支持查询、重置、分页、导出模拟、详情抽屉。
- 申请单和报销单支持保存草稿、提交审批、撤回、审批通过、审批驳回；Demo 可用按钮模拟不同角色操作。
- 关联营销事项弹窗标题按原设计显示为“关联营销事项信息/营销事项申请信息”，支持按单据编号、申请日期、营销活动、营销事项名称筛选，可多选且同单不可重复。
- 选择营销事项后自动带出营销活动计划分类、营销活动、预算科目、预算组织、申请可用金额。
- 提交备用金申请时校验：核算主体、币种、关联营销事项、本次借款金额、借款类型、收付款账号必填；金额必须大于 0 且不能超过申请可用金额。
- 备用金申请审批通过后，模拟插入专项备用金台账，并更新营销事项状态和预算金额。
- 报销单费用信息支持新增/删除明细，金额合计自动刷新报销合计、价税合计、不含税金额、税额。
- 报销单“冲销借款”按钮触发借款台账选择弹窗，过滤借款人=申请人且未还款金额>0；选择后按钮可隐藏或置灰，避免重复选择。
- 本次冲销金额默认等于未还金额和报销合计中的较小值，允许手动调整，但不能超过未还金额。
- 报销单提交时校验：至少一条费用信息、至少一条营销事项预算信息；如有发票，发票价税合计应与费用金额有明显提示；如付款金额>0，收付款账号必填。
- 报销单审批通过后，按是否关联借款分别更新借款台账、预算台账、营销事项申请台账、发票余额台账和营销事项费用台账。
- 还款申请从台账行内进入，默认带出借款金额、已还款金额和未还款金额；审批通过后刷新台账完结状态。
- 台账详情展示来源申请单、报销/还款记录、付款记录、审批记录和金额流水，便于演示闭环。

## 第三方系统处理方式

- OA 审批、金蝶付款申请、CBS 支付、金蝶凭证、发票查验、线下发票接收、退票重付全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换审批状态，记录审批人、审批日期和意见。
  - “模拟生成付款申请”：付款状态变为付款中，生成付款申请号。
  - “模拟 CBS 支付成功”：写入实际支付日期、付款状态、凭证号，单据进入已完成。
  - “模拟 CBS 支付失败”：付款状态变为付款失败，展示失败原因，可重试。
  - “模拟发票查验”：发票状态变为查验通过或查验失败，不调用真实发票平台。
  - “模拟生成凭证”：回写凭证号和最近同步时间。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不读取真实发票，不上传真实附件，不连接真实 OA/金蝶/CBS/银行/发票系统。

## UI/UX 重点

- 整体是 B 端财务单据和台账页面，信息密度适中，突出金额、状态和关联单据。
- 单据页用分组区块：申请信息、申请及借款信息/费用信息、事项申请及预算信息、发票信息、备用金借款信息、付款信息、附件模拟、审批信息。
- 台账页突出筛选区和金额列，金额右对齐、千分位展示；未还款金额、付款失败、逾期还款用明确警示色。
- 状态色明确：草稿为默认，审批中/付款中为处理中，已完成/已完结为成功，驳回/付款失败/查验失败为失败，逾期/部分还款为警示。
- 关联台账选择建议用弹窗或抽屉表格，保留原设计的多选能力和重复选择限制。
- 对“付款金额=0”“无借款报销”“部分冲销”“全额冲销”给出清晰摘要，不用大段说明文字堆在页面上。
- 发票、附件只做模拟列表和状态标签；上传入口可保留，但不要做真实文件解析。
- 列较多的明细表和台账支持横向滚动；关键列建议固定：单据编号、借款人/申请人、金额、状态、操作。

## 验收标准

- 页面名称、核心字段、表单分区、关联台账和台账列与原始详细设计保持一致。
- 至少跑通“备用金申请 -> 审批/付款 -> 专项备用金台账生成 -> 报销冲销 -> 台账更新”闭环。
- 支持无借款个人垫付报销，并能在审批通过后看到预算、事项或费用台账的 mock 更新结果。
- 申请单、报销单、还款申请可保存、提交、审批通过、审批驳回。
- 台账可查询、重置、查看详情，金额汇总和完结状态随操作变化。
- 表单有基础必填和金额校验，关键金额不能小于等于 0，冲销/还款金额不能超过未还款金额。
- 外部系统行为全部为 mock，不发生真实 OA、金蝶、CBS、银行、发票或附件上传调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
