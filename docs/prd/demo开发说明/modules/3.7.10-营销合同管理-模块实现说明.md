# 3.7.10 营销合同管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“营销合同管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

营销合同管理模块用于承接合同系统归档合同，在业财侧完成营销合同结构化复核、财务信息补充、PO 执行、直播计费规则生成和合同履约金额回写：

- 支持查看营销合同台账，展示合同基本信息、财务补充信息、履约金额、PO 金额、摊销/发票/同步状态。
- 支持财务 BP 对合同结构化信息进行复核，补充是否广宣、是否摊销、费用小类、预算科目、结算规则等信息。
- 支持生成合同 PO、达人 PO、直播任务确认单和直播坑位费结算单，并在审批通过后 mock 写入费用预估或直播计费规则台账。
- 支持按合同编号和营销活动汇总 PO 下单金额，回写合同履约区的结算中金额、已结算金额、未结算金额。
- 支持合同变更和合同终止的前端状态演示，体现“存在在途单时阻断终止/变更”的业务规则。

Demo 阶段重点跑通“合同导入/新增 -> 结构化复核 -> 财务补充 -> PO 执行 -> 费用预估/直播计费规则生成 -> 合同履约与台账更新”的闭环，不接真实合同系统、达人系统、OA、ERP、发票平台或摊销系统。

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 合同结构化闭环：合同系统 mock 同步一条已归档营销合同 -> 业财自动创建合同台账记录 -> 财务 BP 打开结构化复核 -> 补充是否广宣、是否摊销、预算部门、费用小类、预算科目、结算规则 -> 提交审批 -> 审批通过后合同状态变为已生效，台账展示复核完成。
2. PO 执行闭环：从合同台账或营销计划选择合同 -> 新建合同 PO 或达人 PO -> 明细带出营销计划、营销活动、预算部门、预算科目、费用小类、供应商和核算主体 -> 填写费用金额/下单金额 -> 审批通过 -> 插入单次执行费用预估台账 mock -> 按合同编号和营销活动回写合同履约区金额。
3. 直播闭环：新建直播任务确认单 -> 维护直播达人、排期、坑位费、线下佣金比例和营销计划信息 -> 审批通过 -> 生成直播业务计费规则台账记录 -> 直播坑位费写入直播费用预估台账 -> 后续用直播坑位费结算单模拟 GMV 或 V 任务结算。

可选演示闭环：

- 合同变更：模拟合同系统发起变更 -> 检查是否存在在途 PO/发票/付款/预估 -> 无在途单则创建新版合同复核任务；有在途单则提示先完结。
- 合同终止：从合同台账发起终止 -> 若存在在途单，提示“不允许终止合同”；无在途单则进入财务审批，审批通过后合同状态变为已终止。
- 摊销生成：复核时选择“是否摊销=是” -> 录入摊销开始/结束日期和税率 -> 自动计算不含税摊销总额、日摊销额 -> 生成合同摊销费用台账 mock 记录。

跨模块数据只做 mock 串联：

- 营销计划、营销活动、预算部门、预算科目来自营销计划/预算管理 mock。
- 费用大类、费用小类、发票类目来自基础数据 mock。
- 单次执行费用预估台账、直播费用预估台账、待到票台账、发票台账只做前端 mock 写入或展示，不要求跨模块金额强一致。

- 直播任务确认单：核算主体、供应商、合同编号、直播坑位费合计、预计排期日、排期结束日期、直播达人 ID、直播达人昵称、直播坑位费、线下佣金比例、营销计划、营销活动计划分类、营销活动、店铺、预算部门、预算科目、品牌、渠道、产品简称、业务单元。
- 直播坑位费结算单：核算主体、结算类型、合同编号、供应商、费用金额合计、费用日期、成交 GMV、GMV 费比、费用金额、直播达人昵称、产品简称、机构、场次、税率、发票类型、业务对接人、业务单元、营销计划、营销活动、预算科目、预算部门、店铺、渠道、品牌。

状态枚举：

- 合同状态：待复核、复核中、已生效、变更中、终止审批中、已终止、已驳回。
- 完结状态：未完结、履约中、已完结、已终止。
- 单据状态：草稿、审批中、已驳回、审批通过、已完成。
- 同步状态：未同步、同步中、同步成功、同步失败。
- 在途状态：无在途、有在途、需处理。

关键规则：

- 合同编号、合同标题、签约主体、供应商、经办人、签订时间、开始时间、结束时间、合同金额、合同状态为核心必填。
- 结束时间不能早于开始时间；合同金额、PO 金额、直播坑位费、费用金额必须大于 0。
- 合同明细含税金额 = 数量 * 含税单价；税额 = 含税金额 * 税率；不含税金额 = 含税金额 / (1 + 税率)。
- 是否摊销=是时，摊销开始/结束日期、税率、预算部门、费用小类、营销活动场景、预算科目必填；日摊销额 = 摊销总额（不含税）/ 摊销天数。
- 合同付款区付款金额合计原则上等于合同金额；Demo 可允许保存草稿，但提交时提示差异。
- PO 审批通过后，按合同编号 + 营销活动匹配合同履约区，累加结算中金额或 PO 下单金额。
- 合同履约区应满足：结算中金额 + 已结算金额 + 未结算金额 = 合同金额；Demo 可在详情页用提示标记差异。
- 合同终止前必须校验在途 PO、待到票、待付款、费用预估、摊销记录；有在途单时阻断终止。

## 关键交互

- 营销合同台账支持按合同编号、合同标题、供应商、签约主体、合同状态、完结状态、复核状态、是否摊销、同步状态、日期范围筛选。
- 台账顶部建议展示摘要指标：合同总数、合同总金额、待复核合同数、履约中合同数、在途单合同数、同步失败数。
- 列表行内支持“详情”“结构化复核”“新建 PO”“直播确认”“发起终止”“重试同步”；不同状态下禁用不适用操作。
- 结构化复核页使用只读区 + 财务编辑区：合同基本信息、合同明细、合同付款区以只读或半只读展示，财务信息和结算方式允许编辑。
- 点击“查阅合同系统原件”只打开 mock 预览抽屉，展示文件名、归档时间和来源系统，不解析真实附件。
- 选择合同编号时自动带出供应商、核算主体、合同金额、合同期间、税率、代理商折扣、合同名称。
- 选择营销计划后带出营销活动、预算部门、预算科目、店铺、渠道、品牌；选择营销活动计划分类后过滤营销活动。
- PO 明细金额变化时实时刷新费用金额合计、直播坑位费合计和不含税金额。
- 直播坑位费结算单选择“GMV 进度结算”时显示成交 GMV、GMV 费比并计算费用金额；选择“V 任务”时显示机构、场次、税率、发票类型和业务对接人。
- 审批通过后生成审批记录和操作日志，并按台账规则 mock 写入单次执行费用预估、直播费用预估、直播业务计费规则、待到票或摊销台账。
- 合同详情页展示履约区，PO 子表字段至少包含 PO 执行单号、营销计划、下单金额、预算科目、预算部门、费用小类、费用日期。
- 合同变更和终止均需先执行“模拟在途校验”；校验失败时展示在途单类型、单号、金额和处理建议。
- 导出、同步合同、提交 OA、生成摊销、推送费用预估等按钮全部为模拟行为，只更新前端状态和日志。

## 第三方系统处理方式

- 合同系统、达人系统、广告平台、电商平台、OA 审批、ERP、发票平台、摊销系统、费用预估系统全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟同步合同系统”：创建或更新合同台账，生成来源系统、同步批次号和最近同步时间。
  - “模拟提交 OA”：复核单或 PO 单状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换单据状态，记录审批人、审批日期和意见。
  - “模拟生成摊销台账”：根据摊销字段生成合同摊销费用台账 mock 记录。
  - “模拟写入费用预估”：根据 PO 明细生成单次执行费用预估或直播费用预估 mock 记录。
  - “模拟生成直播计费规则”：根据直播任务确认单写入直播业务计费规则台账。
  - “模拟在途校验”：从 mock PO、发票、付款、预估、摊销记录中判断是否允许变更或终止。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不连接真实合同系统、OA、ERP、达人平台、广告平台、发票平台，不上传或解析真实附件。

## UI/UX 重点

- 整体按财务 B 端后台设计，重点突出合同状态、复核状态、履约金额、PO 金额、摊销状态和同步状态。
- 营销合同台账是模块入口，建议使用筛选区 + 摘要指标 + 表格 + 详情抽屉。
- 合同详情建议使用页内 Tab：基础信息、明细与付款、财务复核、履约/PO、发票与摊销、审批/日志。
- 结构化复核页字段多，按“合同系统只读信息”和“财务补充信息”分区，避免把所有字段铺成一张超长表。
- 合同明细、付款计划、结算方式、PO 明细均使用可横向滚动表格，并固定行号、金额、营销活动、预算科目等关键列。
- 金额统一右对齐、千分位展示；合同金额、PO 金额、已结算/未结算金额要能一眼比较。
- 状态标签明确：待复核/草稿为默认，审批中/同步中/履约中为处理中，已生效/已完成为成功，已驳回/同步失败为失败，已终止为禁用。
- 直播相关页面要突出达人、排期、坑位费、佣金比例和营销计划关联，避免被合同字段淹没。
- 空状态提供“模拟同步合同”或“重置筛选”；错误状态提供“重试同步”或“查看失败原因”。
- 附件只展示文件名、上传人、上传时间和 mock 状态，不做真实文件处理。

## 验收标准

- 页面名称、核心字段、表单分区、合同复核、PO 执行、直播计费规则和台账更新关系与原始详细设计保持一致。
- 至少跑通“模拟合同同步 -> 合同结构化复核 -> 审批通过 -> 合同台账复核状态更新”的闭环。
- 至少跑通“合同台账 -> 新建合同 PO/达人 PO -> 审批通过 -> 写入单次执行费用预估 -> 合同履约金额回写”的闭环。
- 至少跑通“直播任务确认单 -> 审批通过 -> 生成直播业务计费规则 -> 写入直播费用预估”的闭环。
- 合同台账可按合同编号、供应商、合同状态、完结状态、复核状态、同步状态查询，支持重置、详情查看和导出模拟。
- 结构化复核页能展示只读合同信息，支持补充财务信息、结算规则和摊销信息，并有基础必填、日期、金额校验。
- PO 单据能根据合同编号、营销计划和营销活动带出供应商、核算主体、预算科目、预算部门、费用小类等核心字段。
- 直播结算类型切换时，GMV 进度结算和 V 任务的重点字段能正确显示和校验。
- 合同终止能执行 mock 在途校验；存在在途单时阻断并展示原因，无在途单时可审批通过并更新合同状态。
- 外部系统行为全部为 mock，不发生真实合同系统、OA、ERP、达人平台、广告平台、发票平台或附件上传调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
