# 3.7.17 销售合同模块实现说明

本文用于指导 Gemini 和 Codex 实现“销售合同”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

销售合同模块用于承接销售渠道合同的结构化信息，并基于合同结算规则完成销售结算和返利计提的 Demo 闭环：

- 支持维护销售合同结构化信息，展示合同基础信息、条款、结算服务费规则、返利阶梯和履约金额。
- 支持按合同生成销售合同结算单，录入本期销售、客退、活动承担、包邮和服务费数据，自动计算本期服务费金额和结算金额合计。
- 支持按合同和计提月份生成销售返利计提单，录入本月销售额、累计销售额、返利比例、返利金额和已计提返利，自动计算本期应计提返利。
- 支持审批通过后回写合同履约区、结算单状态、返利计提状态和相关台账摘要。

Demo 阶段重点跑通“销售合同结构化 -> 生成结算单 -> 审批结算 -> 生成返利计提单 -> 审批计提 -> 合同台账状态更新”的闭环，不接真实合同系统、电商平台、ERP、OA 或财务凭证系统。

说明：

- `销售合同结构化.md` 包含合同基础信息、合同条款区、结算区、返利信息和合同履约区；Demo 应优先保留这些分区。
- `销售合同结构化.md` 的信息收集样例包含得物、京东、唯品会、抖音等渠道合同，可作为 mock 客户、合同、服务费率和条款样例。
- `销售合同结算单.md` 明确本期服务费金额 = 本期交易成功金额 * 服务费率，结算金额合计 = 结算明细区本期服务费金额合计。
- `销售返利计提单.md` 明确返利金额合计 = 本期应计提返利合计值，本期应计提返利 = 返利金额 - 已计提返利。
- 原始文档没有完整台账页说明，Demo 可按成熟 B 端后台规范补一个“销售合同台账/工作台”和详情抽屉，承接列表查询、状态回写和演示入口。

| 销售合同结构化 | 合同规则维护页 | 新增/编辑合同、维护基础信息、条款、服务费规则、返利阶梯、提交审批 |
| 销售合同详情 | 合同全景页 | 查看基础信息、条款、结算规则、返利阶梯、履约金额、关联结算单和计提单 |
| 销售合同结算单 | 渠道销售服务费结算 | 选择合同、录入销售结算明细、自动计算服务费、上传 mock 附件、提交审批 |
| 销售返利计提单 | 销售返利月度计提 | 选择合同和月份、录入销售额与返利数据、自动计算本期应计提、提交审批 |

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 合同结构化闭环：从销售合同台账新增或模拟同步一条销售合同 -> 维护合同标题、合同编码、签约主体、客户、合同期间、销售渠道、结算服务费率、返利阶梯 -> 提交审批 -> 审批通过后合同状态变为已生效，合同台账展示结构化完成。
2. 销售结算闭环：从已生效合同新建销售合同结算单 -> 自动带出核算主体、客户/供应商、服务费率 -> 录入本期销售成功金额、客退金额、品牌承担活动金额、交易成功金额 -> 自动计算本期服务费金额和结算金额合计 -> 审批通过后回写合同履约区的结算中金额/已结算金额。
3. 返利计提闭环：从合同或结算结果新建销售返利计提单 -> 选择计提月份 -> 带出合同编号、客户、返利阶梯建议比例和上月累计销售额 -> 录入本月销售额、返利金额、已计提返利 -> 自动计算本期应计提返利 -> 审批通过后更新返利计提台账和合同履约摘要。

可选演示闭环：

- 审批驳回：结算单或返利计提单提交后被驳回，状态回到可编辑，保留审批意见。
- 同步失败：模拟合同系统或电商平台数据同步失败，展示失败原因和重试入口。
- 阶梯返利命中：根据上月累计销售额 + 本月销售额匹配合同返利阶梯，给出返利比例建议，允许业务手动调整并记录说明。

跨模块数据只做 mock 串联：

- 客户、核算主体、销售渠道、费用小类、营销活动场景来自基础数据 mock。
- 销售订单金额、客退金额、活动承担金额可模拟来自电商平台或渠道账单。
- 审批、ERP 入账、凭证、发票和应收/应付联动只做前端状态展示，不要求跨模块金额强一致。

## 主要字段建议

销售合同台账字段：

- 合同编码、合同标题、签约主体、核算主体、客户、销售渠道、合同状态、完结状态、开始时间、结束时间。
- 服务费率、结算规则摘要、返利阶梯摘要、合同条款摘要、备注。
- 结算中金额、已结算金额、未结算金额、累计销售额、累计服务费、累计计提返利。
- 来源系统、同步状态、最近同步时间、同步批次号、失败原因、审批状态、创建人、创建时间。

销售合同结构化字段：

- 合同基本信息：合同标题、合同编码、签约主体、核算架构/核算主体、客户、开始时间、结束时间、合同状态、完结状态、销售渠道。
- 合同条款区：条款信息、备注。
- 结算区：行号、营销活动场景、费用小类、服务费率。
- 返利信息：行号、最小阶梯销售额、最大阶梯销售额、返利百分比。
- 合同履约区：行号、结算中金额、已结算金额、未结算金额。

销售合同结算单字段：

- 主表区：单据编号、申请日期、申请人、申请人公司、申请人部门、申请人岗位、核算主体、合同编号、供应商/客户、结算金额合计、说明、单据状态。
- 费用结算信息：本期销售成功订单数量、本期销售成功订单金额、本期客退数量、本期客退金额、本期品牌承担活动金额、本期包邮金额、本期交易成功数量、本期交易成功金额、服务费率、本期服务费金额。
- 附件区：附件名称、附件类型、上传人、上传时间、mock 预览状态。
- 审批区：行号、流程环节名称、审批人、审批日期、审批意见。

销售返利计提单字段：

- 主表区：单据编号、申请日期、申请人、申请人公司、申请人部门、申请人岗位、核算主体、返利金额合计、说明、单据状态。
- 返利计算明细：计提月份、合同编号、客户、本月销售额、上月累计销售额、累计销售额、返利比例、返利金额、已计提返利、本期应计提返利。
- 审批区：行号、流程环节名称、审批人、审批日期、审批意见。

状态枚举：

- 合同状态：草稿、待审批、已生效、已驳回、已终止、已失效。
- 完结状态：未完结、履约中、已完结。
- 单据状态：草稿、审批中、已驳回、审批通过、已完成、已作废。
- 结算状态：未结算、结算中、已结算、部分结算。
- 计提状态：未计提、计提中、已计提、部分计提。
- 同步状态：未同步、同步中、同步成功、同步失败。

关键规则：

- 合同标题、合同编码、签约主体、客户、开始时间、结束时间、合同状态、完结状态、销售渠道为核心必填。
- 合同结束时间不能早于开始时间；服务费率和返利百分比应在 0-100% 之间。
- 返利阶梯应按销售额区间递增；最小阶梯销售额不能大于最大阶梯销售额。
- 本期服务费金额 = 本期交易成功金额 * 服务费率。
- 结算金额合计 = 结算明细区本期服务费金额合计。
- 累计销售额 = 上月累计销售额 + 本月销售额。
- 本期应计提返利 = 返利金额 - 已计提返利，不能小于 0；如小于 0，提交时提示需调整说明。
- 结算单和返利计提单审批通过后才能回写合同履约区和台账金额。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态：

- `salesContracts`：销售合同台账 12-20 条，覆盖得物、京东、唯品会、抖音等渠道，状态包含草稿、待审批、已生效、已驳回、已终止、同步失败。
- `salesContractSettlementRules`：合同服务费规则 12-20 条，覆盖服务费、平台服务费、供应链费用、包邮补贴等费用小类。
- `salesRebateTiers`：返利阶梯 12-30 条，覆盖不同合同、不同销售额区间和返利比例。
- `salesSettlementForms`：销售合同结算单 8-12 条，覆盖草稿、审批中、已驳回、审批通过、已完成。
- `salesRebateAccrualForms`：销售返利计提单 8-12 条，覆盖不同计提月份、不同返利比例和计提状态。
- `salesContractPerformance`：合同履约摘要，记录结算中金额、已结算金额、未结算金额、累计服务费、累计计提返利。
- `approvalRecords`、`operationLogs`、`syncLogs`：审批、操作和同步记录。

样例数据要能串起来：

- 一条“得物代销合作协议”，服务费率 15%，本期交易成功金额 5,117,072 元，自动计算本期服务费金额 767,560.80 元。
- 一条“京东自营产品购销协议”，带 45 天账期说明和退货/滞销条款摘要，用于展示长条款折叠。
- 一条“唯品会商品销售合同”，存在同步失败原因“渠道账单字段缺失”，可点击重试同步。
- 一条“抖音渠道销售合同”，配置 2-3 档返利阶梯，用于演示阶梯命中和返利计提。
- 一条审批驳回的结算单，驳回原因为“附件缺少渠道结算明细”，可重新提交。

## 关键交互

- 销售合同台账支持按合同编码、合同标题、客户、签约主体、销售渠道、合同状态、完结状态、同步状态、合同期间筛选。
- 台账顶部建议展示摘要指标：合同总数、已生效合同数、本月结算金额、本月计提返利、同步失败数。
- 列表行内支持“详情”“编辑结构化”“新建结算单”“新建返利计提单”“重试同步”；未生效合同禁用新建结算和返利计提。
- 销售合同结构化页按“合同基本信息 + 条款信息 + 结算信息 + 返利信息 + 合同履约区”分区。
- 条款信息较长时使用折叠文本或抽屉预览，首屏只展示摘要和关键结算条款。
- 选择合同编号时自动带出核算主体、客户/供应商、销售渠道、服务费率、合同期间和返利阶梯。
- 结算单录入本期交易成功金额或服务费率时，实时刷新本期服务费金额和结算金额合计。
- 返利计提单选择计提月份后，自动带出上月累计销售额、已计提返利和建议返利比例。
- 返利比例可根据累计销售额命中阶梯自动建议；用户手动修改时要求填写说明或在操作日志中记录。
- 提交审批后状态从草稿变为审批中；审批通过后回写台账金额；审批驳回后允许编辑并重新提交。
- 附件只做 mock 展示，支持添加附件名称、预览占位和删除，不上传真实文件。
- 导出、同步合同、同步渠道账单、提交 OA、生成凭证全部为模拟行为，只更新前端状态和日志。

## 第三方系统处理方式

- 合同系统、电商平台/渠道后台、OA 审批、ERP、财务凭证、发票平台全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟同步合同”：创建或更新销售合同台账，生成来源系统、同步批次号和最近同步时间。
  - “模拟同步渠道账单”：生成销售结算明细，或展示同步失败原因。
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换单据状态，记录审批人、审批日期和审批意见。
  - “模拟生成凭证”：生成 `PZ-YYYYMM-####` 凭证号并回写单据，不连接真实 ERP。
  - “模拟导出”：toast 提示已生成导出任务，不创建真实文件。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不连接真实合同系统、得物/京东/唯品会/抖音后台、OA、ERP、发票平台，不上传真实附件。

## UI/UX 重点

- 整体按财务 B 端后台设计，突出合同状态、销售渠道、服务费率、结算金额、返利金额和同步状态。
- 销售合同台账是模块入口，建议使用筛选区 + 摘要指标 + 表格 + 详情抽屉。
- 合同详情建议使用页内 Tab：基础信息、条款信息、结算规则、返利阶梯、履约记录、审批/日志。
- 结算单和返利计提单按“主表信息 + 明细计算 + 附件/说明 + 审批信息”组织，避免把字段堆成超长表。
- 金额统一右对齐、千分位展示；服务费率、返利比例使用百分比格式。
- 长条款、备注和失败原因要可展开查看，列表中只展示摘要。
- 状态标签明确：草稿/未同步为默认，审批中/同步中/结算中/计提中为处理中，已生效/已完成/同步成功为成功，已驳回/同步失败为失败，已终止/已失效为禁用。
- 表格关键列建议固定：合同编码、客户、销售渠道、状态、服务费率、结算金额/返利金额、操作。
- 空状态提供“新增销售合同”或“模拟同步合同”；错误状态提供“重试同步”和“查看失败原因”。

## 验收标准

- 页面名称、核心字段、表单分区、计算规则与原始详细设计保持一致。
- 至少跑通“新增/同步销售合同 -> 销售合同结构化 -> 审批通过 -> 销售合同台账状态更新”的闭环。
- 至少跑通“已生效合同 -> 新建销售合同结算单 -> 自动计算服务费 -> 审批通过 -> 合同履约金额回写”的闭环。
- 至少跑通“已生效合同 -> 新建销售返利计提单 -> 自动计算本期应计提返利 -> 审批通过 -> 返利台账更新”的闭环。
- 销售合同台账可查询、重置、查看详情、导出模拟；结算单和返利计提单可新增、编辑、提交、审批通过、驳回。
- 关键校验可用：必填校验、日期区间校验、金额不能小于 0、比例在 0-100%、服务费和本期应计提返利自动计算。
- 第三方系统行为全部为 mock，不发生真实合同系统、电商平台、OA、ERP、发票平台或附件上传调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
