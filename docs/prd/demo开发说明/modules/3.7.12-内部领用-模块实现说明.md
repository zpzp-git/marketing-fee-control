# 3.7.12 内部领用模块实现说明

本文用于指导 Gemini 和 Codex 实现“内部领用”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

内部领用模块用于承接 BPM 侧已经履约完成、可真实入账的内部领用数据，在业财中台生成内部领用单据、占用/消耗预算，并形成内部领用台账：

- 支持从 BPM mock 数据生成内部领用单，自动带出申请人、组织、领用明细、业务用途、SKU、数量、单价和预算映射信息。
- 支持内部领用单提交审批、审批通过、驳回和关闭的前端状态流转。
- 支持按预算部门、预算科目汇总预算区金额，审批通过后模拟更新预算实际发生额。
- 支持审批通过后按明细插入内部领用台账，供后续查询、详情查看和导出模拟。
- 支持 BPM 推送失败、预算映射缺失、预算不足等 Demo 异常样例展示。

Demo 阶段重点跑通“BPM 数据推送 -> 生成内部领用单 -> 审批通过 -> 预算发生额更新 -> 内部领用台账生成”的闭环，不接真实 BPM、预算系统、ERP 或总账系统。

## Demo 业务闭环

优先实现 2 条可演示闭环：

1. 自动推送闭环：BPM 推送记录选择一条“待生成”数据 -> 点击“模拟生成内部领用单” -> 系统自动带出申请人、申请日期、核算主体、二级部门、领用日期、业务用途、SKU、数量和单价 -> 自动计算实付金额和实付金额合计 -> 根据组织机构映射预算部门、根据 BPM 业务用途映射预算科目 -> 汇总预算区 -> 提交审批 -> 审批通过后更新预算实际发生额并插入内部领用台账。
2. 异常处理闭环：BPM 推送记录存在“预算映射缺失”或“预算不足”样例 -> 生成单据时标记异常 -> 用户补齐预算科目或调整金额后重新校验 -> 校验通过后提交审批 -> 审批通过并关闭异常状态。

可选演示闭环：

- 审批驳回：内部领用单提交后被驳回，单据回到可编辑状态，预算占用释放，修改明细后重新提交。
- 预算追溯：从内部领用台账详情查看预算区汇总和预算更新日志，展示“发生数=+金额”的 mock 操作。
- 导出模拟：台账按核算主体、领用月份筛选后点击导出，toast 提示生成导出任务，不创建真实文件。

跨模块数据只做 mock 串联：

- 预算部门、预算科目来自预算管理/基础数据 mock。
- SKU、品牌来自产品主数据 mock。
- BPM 业务用途和场景描述来自 BPM 推送 mock。
- 预算台账实际发生额只在前端 mock 数据中更新，不要求跨模块强一致。

## 主要字段建议

内部领用单主表区：

- 单据编号、单据名称、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 实付金额合计、单据状态、审批状态、来源系统、BPM 单号、推送批次号、同步状态、失败原因。

内部领用明细：

- 行号、核算主体、二级部门、领用日期、BPM 业务用途、BPM 场景描述。
- SKU 编码、SKU 名称、品牌、订购数量、单价、实付金额。
- 预算部门、预算科目、一级预算科目、预算校验状态、预算校验说明。

预算区：

- 行号、预算部门、预算科目、一级预算科目、金额、预算可用金额、预算占用金额、预算发生额、预算状态。

审批区：

- 行号、流程环节名称、审批日期、审批人、审批意见、审批结果。

内部领用台账：

- 单据编号、核算主体、申请人、申请日期、领用日期、领用月份、BPM 业务用途、BPM 场景描述。
- SKU 名称、品牌、订购数量、单价、实付金额、预算部门、预算科目、一级预算科目、二级部门。
- 来源系统、BPM 单号、审批状态、预算更新状态、最近更新时间。

状态枚举：

- 单据状态：草稿、待校验、审批中、已驳回、审批通过、已完成、已关闭。
- BPM 推送状态：待生成、已生成、推送失败、重复推送、已忽略。
- 预算校验状态：未校验、校验通过、预算不足、映射缺失、已占用、已发生。
- 同步状态：未同步、同步中、同步成功、同步失败。

关键规则：

- 申请日期、申请人、申请人公司、申请人部门、申请人岗位默认从登录人 mock 自动带出，只读展示。
- 实付金额 = 订购数量 * 单价；实付金额合计 = 内部领用明细实付金额合计。
- 预算部门按“组织机构 -> 预算部门”映射自动带出，允许在 Demo 中手动修正缺失映射。
- 预算科目按“BPM 业务用途 -> 预算科目”映射自动带出，一级预算科目取预算科目父节点。
- 预算区按预算部门 + 预算科目汇总内部领用明细金额。
- 提交审批前校验核算主体、二级部门、领用日期、BPM 业务用途、SKU、订购数量、单价、预算部门必填；订购数量和单价必须大于 0。
- 预算校验通过后才允许提交审批；预算不足或映射缺失时阻断提交并展示原因。
- 审批通过后才真正插入内部领用台账，并将预算区金额计入预算实际发生额。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `internalUseApplications`：内部领用单 8-12 条，覆盖草稿、审批中、已驳回、已完成、预算不足、映射缺失。
- `internalUseLedger`：内部领用台账 12-20 条，覆盖不同核算主体、领用月份、业务用途、预算部门、预算科目和品牌。
- `bpmInternalUsePushes`：BPM 推送记录 8-12 条，覆盖待生成、已生成、推送失败、重复推送、映射缺失。
- `internalUseLines`：内部领用明细 20-40 条，覆盖多 SKU、多部门、多预算科目。
- `budgetMappings`：组织机构到预算部门、BPM 业务用途到预算科目的映射关系，包含 1-2 条缺失映射样例。
- `budgetBalances`：预算余额 mock，包含预算总额、已占用、已发生、可用金额，保留一条预算不足样例。
- `productOptions`：SKU/产品 mock，包含 SKU 编码、SKU 名称、品牌、默认单价、产品状态。
- `approvalRecords`、`operationLogs`、`syncLogs`：审批、预算更新、BPM 推送和操作日志。

样例数据要能串起来：

- 一条“抖音直播样品内部领用”记录，3 个 SKU，总金额 15600 元，审批通过后生成 3 条台账明细。
- 一条“品牌活动赠品内部领用”记录，同一预算部门下多个预算科目，预算区自动汇总为多行。
- 一条“BPM 业务用途未映射预算科目”的异常记录，用于展示映射缺失和手动修正。
- 一条“预算可用金额不足”的记录，用于展示预算校验失败和不可提交。
- 一条审批驳回记录，保留驳回意见并允许重新编辑提交。

## 关键交互

- 内部领用台账支持按核算主体、领用月份、申请人、预算部门、预算科目、BPM 业务用途、品牌筛选。
- 台账顶部建议展示摘要指标：本月领用金额、内部领用单数、SKU 数量、预算发生金额、异常单数。
- 台账行内支持“详情”“查看来源单据”“预算日志”；已完成记录只读展示。
- BPM 推送记录支持“模拟推送”“重新推送”“忽略重复数据”；推送失败展示失败原因和重试入口。
- 生成内部领用单时，如果同一 BPM 单号已生成过单据，提示重复推送并阻断再次生成。
- 内部领用单的领用明细支持新增/删除 mock 行，也支持从 BPM 推送自动生成；自动生成的数据默认只读，允许 Demo 管理员修正预算字段。
- SKU 选择后自动带出品牌和默认单价；数量或单价变化时实时刷新行实付金额、主表合计和预算区汇总。
- 预算科目变化时自动刷新一级预算科目；预算部门或预算科目缺失时在行内展示错误标记。
- 点击“预算校验”后，预算区展示可用金额、占用金额和校验结果；校验失败时阻断提交审批。
- 提交审批后生成审批记录，单据状态变为审批中，按钮切换为“模拟审批通过”“模拟驳回”“撤回”。
- 审批通过后生成内部领用台账记录，预算状态变为已发生，BPM 推送状态变为已生成。
- 审批驳回或撤回时释放预算占用，单据回到可编辑状态。
- 导出、同步 BPM、更新预算、推送总账全部只做前端反馈和状态更新。

## 第三方系统处理方式

- BPM、预算系统、产品主数据、组织主数据、ERP、总账、OA 审批全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟 BPM 推送”：从内置 mock 生成推送批次和内部领用明细。
  - “模拟重新推送”：将失败记录恢复为待生成或已生成，并记录最近同步时间。
  - “模拟预算校验”：根据 mock 预算余额返回校验通过、预算不足或映射缺失。
  - “模拟提交审批”：单据状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换审批状态，记录审批人、审批日期和意见。
  - “模拟更新预算”：审批通过后把预算区金额写入 mock 预算实际发生额。
  - “模拟导出”：toast 提示已生成导出任务，不创建真实文件。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不连接真实 BPM、预算系统、ERP、总账、OA，不调用真实产品或组织主数据接口。

## UI/UX 重点

- 整体按财务 B 端后台设计，突出核算主体、领用月份、业务用途、SKU、实付金额和预算状态。
- 内部领用台账作为模块入口，建议使用筛选区 + 摘要指标 + 表格 + 详情抽屉。
- 内部领用单按“申请信息、内部领用明细、预算区、审批记录、操作日志”分区。
- 明细表和预算区均为横向表格，固定行号、SKU 名称、实付金额、预算部门、预算科目等关键列。
- 金额统一右对齐、千分位展示；订购数量、单价、实付金额和预算汇总要能一眼对齐。
- 状态标签明确：草稿/待生成为默认，审批中/同步中为处理中，已完成/校验通过为成功，已驳回/推送失败/预算不足/映射缺失为失败或警示。
- 预算异常要在明细行和预算区同时可见，避免只靠 toast 提示。
- 空状态提供“模拟 BPM 推送”或“重置筛选”；错误状态提供“重新推送”或“重新校验”。
- 不做真实附件上传；如需要展示 BPM 原始单据，可用 mock 文件名和推送批次抽屉展示。

## 验收标准

- 页面名称、核心字段、表单分区、台账列和预算更新关系与原始详细设计保持一致。
- 至少跑通“BPM 推送记录 -> 生成内部领用单 -> 预算校验 -> 提交审批 -> 审批通过 -> 内部领用台账插入 -> 预算实际发生额更新”的闭环。
- 内部领用台账可按核算主体、领用月份、预算部门、预算科目、BPM 业务用途查询，支持重置、详情查看和导出模拟。
- 内部领用单能自动计算实付金额、实付金额合计，并能按预算部门 + 预算科目生成预算区汇总。
- 预算部门和预算科目能按 mock 映射自动带出；映射缺失时能提示并允许 Demo 修正。
- 提交审批前能校验必填、金额大于 0、预算映射和预算可用金额。
- 审批通过后台账和预算 mock 数据可见变化；审批驳回或撤回时释放预算占用并允许重新提交。
- BPM 推送失败、重复推送、预算不足、映射缺失等异常状态有可演示样例和处理入口。
- 外部系统行为全部为 mock，不发生真实 BPM、预算系统、ERP、总账、OA 或主数据接口调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
