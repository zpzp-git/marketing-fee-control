# 3.7.1 基础数据模块实现说明

本文用于指导 Gemini 和 Codex 实现“基础数据”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

基础数据模块负责维护营销费控系统的核心主数据：

- 费用类型、费用大类、费用小类及其核算/发票/使用部门配置。
- 营销活动及其与预算科目、费用类型、店铺、渠道、业务单元的关系。
- 投放账户、投放方式变更记录、账户注销状态。
- 三方账户的开立、变更、关闭和台账查询。
- 预算科目的新增和禁用申请。

Demo 阶段目标是让后续预算、事项、合同、付款、对账等模块能引用这些 mock 主数据，并能展示“申请 -> 审批 -> 台账更新”的闭环。

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 费用类型闭环：费用类型台账 -> 新增费用类型 -> 财务补充核算科目/发票类目/使用部门 -> 审批通过 -> 费用类型台账新增记录；再从台账发起调整 -> 审批通过 -> 台账状态或科目更新。
2. 营销活动闭环：营销活动管理 -> 新增活动并选择预算科目、费用小类、店铺 -> 审批通过 -> 营销活动与费用关系台账生成关系；再发起关系变更或状态变更 -> 审批通过 -> 关系台账更新。
3. 账户闭环：投放账户或三方账户台账 -> 新增/变更/关闭申请 -> 审批通过 -> 对应账户台账状态、联系人、投放方式或关闭标识更新。

预算科目申请作为支撑闭环：新增/禁用预算科目审批后，更新营销活动表单中的预算科目下拉 mock 数据。

## 主要字段建议

通用单据字段：

- 单据编号、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 单据状态：草稿、审批中、已驳回、审批通过、已关闭。
- 审批信息：流程环节名称、审批人、审批日期、审批意见。
- 附件：只保留文件名、大小、上传时间，不做真实上传。

费用类型字段：

- 申请类型：费用类型、费用大类、费用小类、费用大小类。
- 费用类型、选择费用类型、费用大类、选择费用大类、费用小类。
- 使用部门、预算科目、经分科目、核算科目、发票类目/发票科目。
- 是否允许无票报销、状态、启用时间、费用类型说明、业务说明、财务说明。

营销活动字段：

- 营销活动名称、营销活动类型、一级预算科目、二级预算科目。
- 是否到店铺、店铺、渠道、业务单元、业务来源。
- 能否到品类、能否到 SKU、是否允许个人垫付、是否允许无票报销。
- 费用类型、费用大类、费用小类、经分科目、核算科目、发票科目。
- 营销活动状态、关系状态、启用日期、是否做过变更。

投放账户字段：

- 公司手机号、公司邮箱、结算主体/核算主体、供应商名称、投放平台。
- 投放账户名称、投放账户 ID、投放方式、投放方式生效时间。
- 营销活动、充值方式、是否存在充值赠送、是否存在销售返利。
- 是否为资金充值账户、是否通过此账户申请开票、业务对接人、财务对接人。
- 账户状态、数据是否需要回收、数据已全部回收、投放账户已清账、是否做过变更。

三方账户字段：

- 账户名称、账号、核算主体、店铺、公司手机号、公司邮箱。
- 业务对接人、财务对接人、账户平台、账户属性、账户性质、账户状态、是否做过变更。
- 是否需要付款验证、付款方账号、收款方账号、付款方式、付款金额、实际支付日期、摘要。
- 关闭时增加：账户余额是否已处理、关闭说明、关闭材料。

预算科目字段：

- 申请类型：新增预算科目、预算科目禁用。
- 选择申请/禁用预算科目类型：预算二级科目、预算一级科目&预算二级科目。
- 预算组织、选择一级预算科目、一级预算科目、二级预算科目、预算科目申请说明。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实系统：

- `expenseTypes`：12-20 条，覆盖推广费用、达人费用、直播费用、平台服务费、样品费用等；状态含已启用、未生效、已禁用。
- `marketingActivityRelations`：12-20 条，覆盖抖音、天猫、京东、小红书等渠道；活动状态含启用、禁用；关系状态含启用、停用、待生效。
- `adAccounts`：8-15 条，覆盖巨量引擎、腾讯广告、阿里妈妈、京准通；状态含已启用、审批中、已注销；至少 2 条有投放方式变更历史。
- `adAccountMethodChanges`：按投放账户记录投放方式、生效时间、结束时间。
- `thirdPartyAccounts`：8-15 条，覆盖平台账户、保证金账户、资金账户；状态含已启用、已关闭、审批中。
- `budgetSubjects`：一级/二级树形 mock，例如品牌推广、渠道营销、达人合作、直播运营、平台费用。
- `baseDataApplications`：统一存放申请单 mock，区分费用类型申请、活动申请、账户申请、预算科目申请，便于审批记录复用。

样例状态要有可演示差异：

- 一条费用类型审批中，一条已驳回，一条未生效。
- 一条营销活动关系待生效，一条活动已禁用。
- 一条投放账户数据未全部回收，无法直接注销完成。
- 一条三方账户需要付款验证，提交后显示模拟付款记录。

## 关键交互

- 列表页统一支持查询、重置、分页、导出模拟、详情抽屉。
- 台账行内操作按状态显示：启用中的记录可发起变更/关闭，审批中记录只可查看，已关闭/已注销记录不可再次操作。
- 表单支持保存草稿、提交审批、撤回、审批通过、审批驳回；Demo 可用按钮模拟不同角色操作。
- 费用类型新增根据“申请类型”动态显示字段：
  - 费用类型：填写费用类型、使用部门。
  - 费用大类：选择费用类型，填写费用大类、核算科目、发票类目、是否允许无票报销、使用部门。
  - 费用小类：选择费用类型和费用大类，填写费用小类及核算/发票信息。
  - 费用大小类：同时填写费用大类和费用小类。
- 费用类型调整从费用类型台账弹窗选择，带出原费用类型、大类、小类、部门、核算科目、发票科目、状态、启用时间。
- 营销活动申请选择店铺后自动带出渠道，选择业务单元后自动带出业务来源；选择费用小类后带出费用大类、核算科目、发票科目。
- 营销活动变更按“关系变更/状态变更”切换区块；已审批通过的活动不允许改名称，只能改关系和状态。
- 投放账户新增如缺公司手机号/邮箱，显示“模拟 OA 申请手机号/邮箱”提示；不跳转真实 OA。
- 投放账户变更勾选“是否变更投放方式=是”时，投放方式和生效时间必填，并写入投放方式变更台账。
- 投放账户注销需确认“数据已全部回收”和“投放账户已清账”；未满足时可审批通过但状态停留在清账中/待回收。
- 三方账户申请选择“是否需要付款验证=是”时显示付款区，付款金额必须大于 0；审批后账户状态为已启用。
- 三方账户关闭必须确认账户余额已处理；审批后账户状态更新为已关闭。
- 预算科目申请审批通过后，新增科目出现在营销活动预算科目下拉中；禁用科目不可再被新单选择。

## 第三方系统处理方式

- OA 审批、OA 手机号/邮箱申请、IT 账号转换规则、平台账户开立、投放平台配置、付款验证全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟 OA 审批”：单据进入审批中并生成审批节点。
  - “模拟 OA 申请手机号/邮箱”：为当前申请人生成一个公司手机号或邮箱。
  - “通知 IT 配置规则”：同步状态变为同步中，再变为成功或失败。
  - “模拟付款验证”：生成付款记录，状态为验证通过或验证失败。
  - “批量导入投放账户”：使用内置 mock 数据追加到表格，不读取真实文件。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。

## UI/UX 重点

- 整体是 B 端后台主数据维护，不做营销页风格。
- 台账页信息密度可以略高，突出筛选区、表格列、状态标签和行内操作。
- 单据页用分组区块：申请信息、业务信息/明细区、附件模拟、审批信息、操作记录。
- 对费用类型、营销活动关系、账户状态使用明确状态色：启用/审批通过为成功色，审批中为处理中，待生效/待回收为警示，驳回/同步失败为失败色，关闭/注销为禁用色。
- 关联台账选择建议用弹窗或抽屉表格，支持关键字筛选和多选；选中后自动带出只读字段。
- 对动态区块给出清晰的表单结构，但不要用大段说明文字占页面空间。
- 表格列较多的台账要支持横向滚动、列固定或列密度切换，避免字段挤压。

## 验收标准

- 页面名称、核心字段、状态和台账列与原始详细设计保持一致。
- 至少跑通费用类型、营销活动、账户三条闭环中的一条；建议三条都能演示。
- 新增/变更/关闭类单据可保存、提交、审批通过、驳回。
- 审批通过后，对应台账能看到新增或更新结果。
- 列表页可查询、重置、查看详情，空结果有空状态。
- 表单有基础必填校验，金额字段不能小于等于 0。
- 外部系统行为全部为 mock，不发生真实 OA、IT、平台、付款或文件导入调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
