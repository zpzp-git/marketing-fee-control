# 3.7.9 营销计划管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“营销计划管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

营销计划管理模块用于承接预算、营销活动、合同、PO 执行和费用预估之间的计划层管理：

- 支持业务人员新建营销计划，填写计划名称、分类、期间、使用部门、店铺、渠道、品牌、业务单元等基础信息。
- 支持一个营销计划下维护多条营销活动明细，配置预算科目、预算部门、预估预算、关联合同和费用预估。
- 支持从合同、PO 执行单、费用预估台账、合同履约台账 mock 回写活动执行金额和计划实际使用预算。
- 支持计划状态和活动状态展示，覆盖未开始、进行中、已完成、已终止等演示状态。
- 支持按计划、活动、预算部门、渠道、品牌查看计划执行进度、预算占用和实际结算情况。

Demo 阶段重点是跑通“新建营销计划 -> 维护活动明细 -> 关联预算和合同 -> 提交/生效 -> 模拟 PO/费用预估/履约回写 -> 更新计划状态和金额”的闭环，不做真实达人系统、合同系统、预算系统或第三方平台集成。

原始设计包含 5 个 Sheet：

- `方案一：一个营销计划带多个营销活动`：作为 Demo 主方案，适合展示计划到活动、预算、合同、PO 和实际结算的完整链路。
- `方案二：一个营销计划等于一个营销活动`：作为简化录入方案或“单次执行计划”视图参考。
- `合同结算规则`：用于关联合同后展示结算规则摘要，不在本模块实现复杂结算引擎。
- `预算占用使用方式`：用于展示计划占用预算、费用预估、PO 执行单和合同履约之间的 mock 关系。
- `确认事项`：Demo 中只记录最后一版确认活动，不做活动修改过程管理；活动颗粒度按演示需要合理设置。

整体规划中提到 3.7.9 还包含框架方案、营销计划与达人系统实现方案、会议纪要和 PPT，但当前结构化 md 仅有营销计划页面。实现时以已转换 md 为主，对达人系统衔接只做 mock 展示。

## Demo 业务闭环

优先实现 2 条可演示闭环：

1. 多活动计划闭环：业务人员新建营销计划 -> 填写计划基本信息和使用部门 -> 新增多条营销活动明细 -> 选择预算科目、预算部门和预估预算 -> 关联合同 -> 保存并提交/生效 -> 营销计划台账展示占用预算总额和计划状态。
2. 执行回写闭环：在计划详情或台账点击“模拟回写” -> 从 mock PO 执行单、费用预估台账、合同履约台账带出下单金额、预估费用和实际结算 -> 回写活动明细 -> 汇总实际使用预算 -> 活动状态由未开始变为进行中或已完成 -> 全部活动完成后计划状态变为已完成。

可选演示闭环：

- 单次执行计划：选择计划类型为“单次执行” -> 填写营销活动场景、合同、费用小类、投放平台、达人/主播、任务 ID 和金额 -> 生效后生成一条活动明细和计划台账记录。
- 计划复制：从历史计划复制基础信息和活动配置，但不复制 PO 执行单、预估费用和实际结算数据。
- 计划终止：未完成计划可终止，终止后不允许新增活动或继续回写执行数据，并展示终止原因。

跨模块数据只做 mock 串联：

- 预算科目、预算部门可复用基础数据/预算管理 mock。
- 营销活动场景可复用基础数据中的营销活动配置。
- 合同、PO 执行单、费用预估、合同履约来自营销合同和费用预估模块 mock 数据。
- 达人/主播、投放平台、投放账户只展示 mock 字段，不调用真实达人系统或广告平台。

## 主要字段建议

营销计划基础信息：

- 计划编号、营销计划名称、营销计划分类、计划类型、开始时间、结束时间、使用部门、营销计划状态。
- 占用预算总额、实际使用预算、创建时间、创建人、申请人、申请日期。
- 店铺全称、渠道、品牌、业务单元、业务来源。
- 建议补齐：计划说明、终止原因、最近回写时间、同步状态、失败原因。

状态枚举：

- 计划状态：草稿、未开始、进行中、已完成、已终止、已驳回。
- 活动状态：未开始、进行中、已完成、已终止。
- 合同完结状态：未开始、履约中、已完结、已终止。
- 同步状态：未同步、同步中、同步成功、同步失败。

营销活动明细字段：

- 行号、营销活动场景/营销活动计划分类、活动状态、活动开始时间、活动结束时间。
- 一级预算、预算科目、预算部门、预估预算。
- 关联合同、合同编号、合同名称、合同完结状态、供应商、达人/主播。
- PO 结算单/PO 执行单金额、预估费用、实际结算。
- 建议补齐：费用大类、费用小类、费用日期、投放平台、投放账户 ID、任务 ID、品牌、品类、单品、备注。

PO/费用预估子表字段：

- PO 执行单号、下单金额、预算科目、预算部门、费用小类、费用日期、合同编号。
- 预估单号、预估金额、预估日期、预估方式、来源账单。
- 履约/结算单号、结算金额、结算日期、结算状态。

关键规则：

- 营销计划名称、分类、开始时间、结束时间、使用部门、计划状态必填。
- 活动明细至少 1 行；预算科目、预算部门、预估预算、关联合同建议作为核心必填。
- 结束时间不能早于开始时间；活动起止时间原则上落在计划期间内，Demo 可提示并允许保存草稿，不允许提交生效。
- 占用预算总额 = 活动明细预估预算合计。
- 实际使用预算 = 活动明细实际结算合计。
- 预估预算作为实际占用预算；提交/生效时校验不能超过 mock 预算可用金额。
- 已完成计划不允许修改基础信息和新增活动。
- 进行中和已完成活动不允许删除；复制活动时不复制 PO 执行单、预估费用和实际结算。
- 存在未完成活动时，不允许手工把计划改为已完成。
- 通过使用部门模拟查看权限，通过预算部门模拟活动明细权限；Demo 只做字段展示和筛选，不做真实鉴权。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `marketingPlans`：营销计划台账 12-20 条，覆盖草稿、未开始、进行中、已完成、已终止、已驳回。
- `marketingPlanActivities`：计划活动明细 20-40 条，覆盖不同预算部门、预算科目、合同状态和活动状态。
- `marketingPlanApplications`：新增/编辑计划表单草稿和审批记录 8-12 条。
- `marketingContractOptions`：可关联合同 10-20 条，包含合同编号、合同名称、供应商、合同金额、完结状态、结算规则。
- `poExecutionMock`：PO 执行单 12-20 条，包含 PO 单号、合同编号、下单金额、费用小类、费用日期、预算科目和预算部门。
- `feeEstimateMock`：费用预估台账 12-20 条，包含预估单号、合同编号、预估金额、预估方式和来源账单。
- `contractFulfillmentMock`：合同履约/实际结算 12-20 条，包含履约单号、合同编号、结算金额、结算日期和结算状态。
- `budgetSubjectOptions`：预算科目选项，包含一级预算、二级预算、预算部门、可用预算和管控状态。
- `departmentOptions`、`storeOptions`、`channelOptions`、`brandOptions`、`businessUnitOptions`：基础下拉选项。
- `talentTaskMock`：达人/主播和投放任务 mock，包含达人/主播、投放平台、投放账户 ID、任务 ID、任务金额。
- `approvalRecords`、`operationLogs`、`syncLogs`：审批、操作和同步记录。

样例数据要能串起来：

- 一条“双十一大促计划”，包含直播、达人种草、信息流投放 3 条活动，总预估预算 210000 元。
- 一条进行中计划已有 PO 下单金额和部分实际结算，能演示实际使用预算回写。
- 一条已完成计划所有活动均已完成，不允许编辑和新增活动。
- 一条预算不足计划，提交时展示预算不足提示。
- 一条合同同步失败计划，展示失败原因和“重试模拟回写”入口。
- 一条单次执行达人计划，包含达人/主播、任务 ID、投放平台和一口价合同结算规则。

## 关键交互

- 营销计划台账支持按计划名称、计划分类、计划状态、使用部门、预算部门、渠道、品牌、时间范围筛选。
- 台账顶部建议展示摘要指标：计划数、占用预算总额、实际使用预算、进行中计划数、同步失败数。
- 列表行内支持“详情”“编辑”“复制”“模拟回写”“终止”；不同状态下禁用不适用操作。
- 新增计划默认状态为草稿或未开始，创建时间自动生成，占用预算总额和实际使用预算只读汇总。
- 活动明细支持新增、删除、复制；行内金额变化时实时刷新占用预算总额。
- 选择预算部门后带出可选预算科目和可用预算；选择预算科目后带出一级预算、费用大类/小类。
- 选择关联合同时带出合同编号、供应商、合同完结状态和结算规则摘要。
- 点击活动行的 PO/预估/实际结算字段，打开关联子表弹窗，按合同编号过滤展示对应 mock 台账。
- 点击“模拟回写”时，批量按合同编号回写 PO 执行单金额、预估费用和实际结算，更新最近回写时间。
- 活动状态可由金额自动推导：无执行数据为未开始；有 PO、预估或结算数据为进行中；合同完结且实际结算已回写为已完成。
- 计划状态可由活动状态汇总：全部未开始为未开始；存在进行中为进行中；全部已完成为已完成；终止后固定为已终止。
- 提交/生效时校验必填、日期、活动明细、预算可用金额；校验失败以表单顶部提示和字段错误同时展示。
- 已完成计划不允许编辑和新增活动；已终止计划只允许查看详情和操作记录。
- 终止计划需要填写终止原因，并二次确认；终止后释放预算只做 mock 操作记录，不强求跨模块金额一致。
- 导出、同步、提交审批、推送达人系统等按钮全部是模拟操作，只更新前端状态和日志。

## 第三方系统处理方式

- 达人系统、广告平台、电商平台、合同系统、预算系统、费用预估系统、ERP、OA 审批全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟提交 OA”：计划状态变为审批中或未开始，生成审批记录。
  - “模拟审批通过/驳回”：切换计划状态，记录审批人、审批日期和意见。
  - “模拟占用预算”：根据活动预估预算更新占用预算状态，不调用真实预算服务。
  - “模拟合同回写”：根据合同编号带出供应商、合同状态和结算规则。
  - “模拟 PO 回写”：写入 PO 执行单号和下单金额。
  - “模拟费用预估回写”：写入预估费用金额和预估单号。
  - “模拟履约回写”：写入实际结算金额并更新活动状态。
  - “模拟推送达人系统”：更新同步状态、最近同步时间、同步批次号；失败时展示失败原因。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不连接真实达人系统、合同系统、预算系统、ERP、OA、广告平台或电商平台，不上传或解析真实附件。

## UI/UX 重点

- 整体按 B 端财务运营后台设计，重点突出计划状态、预算占用、实际使用、活动执行进度和同步状态。
- 营销计划台账是模块入口，建议使用筛选区 + 摘要指标 + 表格 + 详情抽屉。
- 新增/编辑页使用分组区块：计划基本信息、活动明细、关联执行数据、审批/操作记录。
- 活动明细是核心区域，建议固定行号、活动场景、预算科目、预算部门、预估预算、关联合同、实际结算等关键列。
- 金额统一右对齐、千分位展示；占用预算和实际使用预算在表单顶部或侧边摘要持续可见。
- 状态标签明确：草稿/未开始为默认，审批中/进行中/同步中为处理中，已完成为成功，已驳回/同步失败为失败，已终止为禁用或警示。
- 关联 PO、预估、实际结算建议用可点击金额或“查看明细”入口，避免在主表里塞入过多列。
- 方案二的单次执行字段较多，可作为“单次执行”模式下的折叠区域，默认保留核心字段：活动场景、合同、费用小类、投放平台、达人/主播、任务 ID、金额。
- 详情页要能解释金额来源，至少展示活动明细、PO 执行单、费用预估、合同履约和操作记录。
- 空状态提供“新建营销计划”或“重置筛选”；错误状态提供“重试模拟回写”。
- 页面不做营销落地页风格，保持信息密度适中、适合现场演示和业务人员扫描。

## 验收标准

- 页面名称、核心字段、表单分区、活动明细和预算/合同/PO 关联关系与原始详细设计保持一致。
- 至少跑通“新建营销计划 -> 新增活动明细 -> 关联预算和合同 -> 生效 -> 台账展示”的闭环。
- 至少跑通“模拟 PO/费用预估/履约回写 -> 活动金额更新 -> 计划实际使用预算和状态更新”的闭环。
- 营销计划台账可按计划名称、状态、使用部门、预算部门、渠道、品牌查询，支持重置、详情查看和导出模拟。
- 新增/编辑计划有基础必填、日期和金额校验；占用预算总额、实际使用预算能自动汇总。
- 活动明细可新增、复制、删除；进行中和已完成活动不允许删除，复制时不复制执行数据。
- 已完成计划不允许修改或新增活动；存在未完成活动时不允许手工改为已完成。
- 关联合同后能展示合同状态、供应商、结算规则摘要，并按合同编号过滤 mock PO/费用预估/履约数据。
- 外部系统行为全部为 mock，不发生真实达人系统、合同系统、预算系统、ERP、OA 或广告平台调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
