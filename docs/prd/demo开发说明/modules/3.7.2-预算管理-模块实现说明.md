# 3.7.2 预算管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“预算管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

预算管理模块负责年度预算、月度滚动预测、预算调整、预算查询和预算管控策略展示：

- 支持业务人员编制年度预算、月度预测和预算调整单。
- 支持模拟提交 OA 审批、业务审批、财务审批、驳回后重新编辑。
- 审批通过后，按预算类型写入或更新对应台账。
- 支持费用/成本预算、收入预算-渠道、收入预算-品类的分维度查询。
- 支持预算汇总、经分报表取数、财务摊销结果、收入挑战目标等查询视图。
- 支持预算管控策略的演示：余额查询、超额提示、超额禁止、特殊审批提示。

Demo 阶段重点是跑通“编制/预测/调整 -> 审批 -> 台账更新 -> 查询汇总”的闭环，不做真实预算引擎和外部系统集成。

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 年度预算闭环：年度预算编制 -> 填写或导入预算明细 -> 提交审批 -> 业务审批通过 -> 财务点击汇总预算并查看汇总结果 -> 财务审批通过 -> 年度预算台账、收入预算台账、汇总年度预算台账更新。
2. 月度预测闭环：月度预测编制 -> 选择预算类型和预算科目 -> 查询年度预算余额并校验 -> 提交审批 -> 审批通过 -> 月度滚动预测结果台账或收入月度预测台账更新。
3. 预算调整闭环：从预算台账查看预算余额 -> 发起预算调整单 -> 录入调增/调减明细 -> 提交审批 -> 审批通过 -> 台账中的预算总额调整数、调整后预算、可用余额变化，并在变更明细中可见。

收入挑战目标和财务摊销结果可作为查询型演示：通过“模拟导入/刷新”生成 mock 数据，不要求与编制单形成完整生产级链路。

## 主要字段建议

通用单据字段：

- 单据编号、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 一级部门、二级部门、三级部门、四级部门、事业部。
- 预算类型：收入-渠道、收入-品类、成本类、费用类。
- 说明/调整事由、附件模拟、单据状态、审批状态。
- 审批信息：流程环节名称、审批人、审批日期、审批意见。

年度预算编制字段：

- 一级部门、二级部门、三级部门、四级部门、预算类型、说明。
- 编制区：行号、一级预算科目、二级预算科目、预算科目属性、事业部、渠道、品类、全年合计、1月-12月。
- 规则：预算类型为收入-渠道时显示渠道；预算类型为收入-品类时显示品类；费用/成本类不显示收入维度。
- 审批通过后：非收入写入年度预算查询台账；收入-渠道写入收入预算查询台账-渠道；收入-品类写入收入预算查询台账-品类。

月度预测编制字段：

- 申请日期、申请人、事业部、一级部门、二级部门、说明、预算类型。
- 查询年度预算按钮/年度预算总额/可用余额/校验结果。
- 编制区：行号、一级预算科目、二级预算科目、预算科目属性、事业部、渠道、品类、年度预算总额、全年合计、1月-12月。
- 规则：全年预测额超过年度预算或月度阈值时，显示超额提示或特殊审批标签。
- 审批通过后：非收入写入月度滚动预测结果台账；收入-渠道/品类分别写入收入月度预测查询台账。

预算调整单字段：

- 调整类型：部门内调整、部门间调整、事业部间调整。
- 调整事由、调增合计、调减合计。
- 预算区：行号、事业部、部门、科目、项目、调整期间、调整方向、调整金额、备注。
- 规则：调整方向为调增时累计调增合计；调整方向为调减时累计调减合计；审批结束后更新预算台账的预算总额调整数。

台账通用字段：

- 单据编号、申请月份、编制年度、事业部、一级部门、二级部门、三级部门、四级部门。
- 一级预算科目、二级预算科目、预算科目属性、渠道、品类、合并口径。
- 全年合计、1月-12月、原预算金额、调整金额、调整后预算、已占用金额、可用余额、变更明细。
- 来源单据、来源系统、同步状态、最近同步时间、失败原因。

预算管控策略字段：

- 控制对象：预算部门、预算科目。
- 控制方式：末级独立、合并总额、分别总额。
- 控制周期：月度、月度累计、期间总额、季度、季度累计、季度内累计、半年、半年累计、半年内累计、年度、多年度总额、历史累计。
- 阈值：提示百分比、禁止百分比、是否启用、策略说明。
- 规则：年度预算超额不允许提单；年度超额可触发特批；月度超额走特殊审批；月度预算达到 70% 弹窗提示。

报表取数字段：

- 一级部门、二级部门、三级部门、四级部门。
- 一级预算科目、二级预算科目。
- 报表科目一级、报表科目二级、报表科目三级。
- 取数来源、汇总口径、更新时间。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `budgetApplications`：年度预算编制单 8-12 条，状态含草稿、审批中、业务已通过、财务已通过、已驳回。
- `forecastApplications`：月度预测编制单 8-12 条，覆盖不同月份、费用类、成本类、收入-渠道、收入-品类。
- `budgetAdjustments`：预算调整单 8-12 条，覆盖部门内调整、部门间调整、事业部间调整，状态含审批中、已通过、已驳回。
- `annualBudgetLedger`：费用/成本年度预算台账 12-20 条，包含全年合计、月度拆分、调整数、可用余额。
- `annualBudgetSummaryLedger`：汇总年度预算台账 8-15 条，按合并口径、预算科目聚合。
- `monthlyForecastLedger`：月度滚动预测结果台账 12-20 条。
- `incomeBudgetByChannel`、`incomeBudgetByCategory`：收入年度预算台账，各 8-15 条。
- `incomeForecastByChannel`、`incomeForecastByCategory`：收入月度预测台账，各 8-15 条。
- `financialAmortizationLedger`：年度预算财务摊销结果 8-15 条。
- `incomeChallengeByChannel`、`incomeChallengeByCategory`：收入挑战目标台账，各 8-15 条。
- `budgetControlPolicies`：预算控制维度和阈值策略 10-15 条。
- `budgetReportMappings`：部门、预算科目、报表科目映射 10-20 条。

样例数据要有演示差异：

- 至少一条年度预算审批中，一条业务驳回，一条财务驳回，一条已生效。
- 至少一条月度预测触发“月度预算达到 70%”提示。
- 至少一条月度预测触发“超年度预算，需特殊审批”。
- 至少一条预算调整为调减后可用余额不足，禁止提交或提示先调整预算。
- 至少一条外部同步失败记录，展示失败原因和重试入口。

## 关键交互

- 列表页统一支持查询、重置、分页、导出模拟、详情抽屉。
- 年度预算编制和月度预测编制支持“手工新增行”和“模拟导入”，导入只使用内置 mock 数据。
- 编制区支持增加行、删除行、复制行、按月录入金额，全年合计可自动汇总，也允许手动录入后校验 1月-12月合计差异。
- 预算类型切换时动态显示渠道或品类字段，并清空不适用维度。
- 选择一级预算科目/二级预算科目后，自动带出预算科目属性。
- 月度预测点击“查询年度预算”后，展示年度预算总额、已占用、已调整、可用余额和校验结果。
- 提交审批时做基础校验：必填字段、金额大于 0、至少一条明细、月份合计与全年合计差异提示。
- 审批流用前端按钮模拟：提交、业务通过、业务驳回、财务通过、财务驳回、撤回。
- 业务或财务驳回后，单据状态回到未提交/已驳回，可编辑并重新提交。
- 财务在年度预算流程中有“汇总预算”动作，点击后刷新汇总年度预算台账并展示汇总结果。
- 财务在月度预测流程中有“汇总预测”动作，点击后刷新月度滚动预测台账。
- 预算调整审批通过后，按调整方向更新台账：调增增加预算总额调整数，调减减少预算总额调整数。
- 台账的“变更明细”用抽屉展示来源单据、调整前金额、调整金额、调整后金额、审批记录。
- 预算管控策略支持“模拟应用到当前单据”，展示提示、禁止或特殊审批结果。
- 查询型台账支持“模拟刷新/同步”，更新最近同步时间和同步状态。

## 第三方系统处理方式

- OA 审批、经营分析系统、ERP、财务摊销、预算导入模板、收入目标导入全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点。
  - “模拟 OA 审批通过/驳回”：切换审批状态并记录审批意见。
  - “模拟导入预算”：从内置 mock 数据生成编制明细。
  - “同步经分报表”：更新同步状态、最近同步时间；可模拟成功或失败。
  - “刷新财务摊销结果”：生成/更新摊销台账，不调用真实财务系统。
  - “导入收入挑战目标”：使用内置 mock 数据刷新挑战目标台账。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不读取真实 Excel，不上传真实附件，不连接真实 OA/ERP/经分/财务系统。

## UI/UX 重点

- 整体是财务预算 B 端后台，信息密度可略高，避免营销落地页风格。
- 表单页用分组区块：申请信息、组织信息、编制/调整明细、预算校验、审批信息、操作记录。
- 编制区和台账列很多，表格要支持横向滚动；关键列建议固定：单据编号、预算科目、全年合计、状态/操作。
- 金额展示统一右对齐，千分位格式，负数/调减用明确色彩区分。
- 顶部摘要建议展示年度预算总额、调整金额、已占用、可用余额、预测差异。
- 状态色明确：草稿/未提交为默认，审批中为处理中，已通过/已生效为成功，驳回/同步失败为失败，超额/特殊审批为警示。
- 台账页突出筛选和汇总行，保留原设计中的“汇总数合计”。
- 预算管控提示要可演示但不阻塞太多流程：提示类用弹窗/Alert，禁止类阻止提交，特殊审批类给单据加标签。
- `年度预算报表-经分` 可做成轻量报表页：筛选区 + 汇总指标 + 报表科目矩阵 + 取数来源说明抽屉。

## 验收标准

- 页面名称、核心字段、表单分区和台账列与原始详细设计保持一致。
- 至少跑通年度预算、月度预测、预算调整三条闭环中的一条；建议三条都能演示。
- 年度预算审批通过后，能在年度预算台账、收入预算台账或汇总预算台账看到新增/更新结果。
- 月度预测审批通过后，能在月度滚动预测或收入月度预测台账看到结果。
- 预算调整审批通过后，预算台账的调整数、调整后预算、可用余额和变更明细发生变化。
- 列表页可查询、重置、查看详情，空结果有空状态。
- 表单有基础必填和金额校验，预算余额不足、超额、达到 70% 等关键规则有可见提示。
- 外部系统行为全部为 mock，不发生真实 OA、ERP、经分、财务摊销或文件导入调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
