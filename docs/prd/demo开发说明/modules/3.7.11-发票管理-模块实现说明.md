# 3.7.11 发票管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“发票管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

发票管理模块用于承接结算后“待到票”事项，支持业务上传/选择发票并发起核销、财务审核签收、凭证号回写、红冲处理和无票核销申请：

- 支持查看待到票台账，按供应商、结算单、营销活动、费用小类、发票状态定位待处理记录。
- 支持新建发票核销单，关联待到票台账、发票信息和预付款台账，审批通过后更新待到票、发票余额、预付款和发票核销台账。
- 支持从发票核销台账发起发票红冲单，审批通过后回退待到票和发票已用金额。
- 支持无票核销申请，覆盖已结算待到票和未结算关联合同两类场景。
- 支持发票核销台账、待到票台账、无票核销申请台账的查询、详情、导出模拟和状态变化展示。

Demo 阶段重点跑通“待到票 -> 发票核销/无票核销 -> 审批 -> 台账更新”和“已核销发票 -> 红冲 -> 审批 -> 台账回退”的闭环，不接真实发票平台、OA、金蝶、ERP 或纸质发票签收系统。

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 发票核销闭环：待到票台账选择一条“发票未到/部分到票”记录 -> 新建发票核销单 -> 供应商、核算主体、结算明细自动带出 -> 上传或选择发票 mock -> 自动计算本次核销合计、未到票余额、价税合计、不含税金额、税额 -> 提交审批时增加待到票占用/到票中金额 -> 审批通过后减少占用、增加已到票金额，必要时状态变为“已到票完结”，插入发票核销台账并生成凭证号。
2. 发票红冲闭环：从发票核销台账选择一条已核销记录 -> 发起红冲单 -> 自动带出发票核销单号、结算单号、供应商、发票信息和已核销金额 -> 填写红冲说明 -> 提交审批 -> 审批通过后减少发票余额台账已用金额，回退待到票已到票金额，未核销余额为 0 时发票状态回到“发票未到”。
3. 无票核销闭环：待到票台账选择允许无票记录 -> 新建无票核销申请单 -> 选择是否已结算；已结算时关联待到票结算明细，未结算时展示合同信息区并关联合同 -> 提交审批 -> 审批通过后待到票状态变为“已无票核销”，插入无票核销申请台账。

可选演示闭环：

- 预付到票：供应商存在预付款余额时显示预付核销区，选择预付池记录，审批通过后将预付款台账“是否到票”更新为“是”。
- 财务驳回：财务审核不通过时单据回到“未提交/已驳回”，释放待到票占用金额，业务可编辑后重新提交。
- 发票校验失败：上传发票 mock 后展示“购方税号不一致”“金额超过结算余额”等失败原因，禁止提交或允许替换发票。

跨模块数据只做 mock 串联：

- 待到票记录可来自营销合同、费用对账结算、付款或结算模块 mock。
- 预付池使用付款管理/供应商预付款台账 mock。
- 凭证号、OA 待办、金蝶总账凭证、发票查验均为前端状态和操作日志模拟。

- 合同信息区：关联合同、合同编号、合同名称、营销活动、合同金额；当“是否已结算=否”时展示并校验必填。
- 结算明细：结算单号、预计付款日期、营销活动计划分类、营销活动、合同编号、合同名称、费用大类、费用小类、结算余额、本次核销金额、未核销余额。

发票核销台账字段：

- 单据编号、单据名称、核销日期、发票核销单号、结算单号、结算日期、核算主体、供应商、营销活动、费用大类、费用小类、结算金额、已核销金额、未核销金额、应付日期、红冲状态、凭证号。

无票核销申请台账字段：

- 单据编号、单据名称、申请日期、核算主体、供应商、合同编号、合同名称、是否已结算、无票申请金额、可用金额、结算单号、使用状态、审批状态。

状态枚举：

- 单据状态：草稿、未提交、审批中、财务待签收、财务待确认、已驳回、审批通过、已完成、已红冲。
- 发票状态：发票未到、部分到票、到票中、已到票完结、已无票核销、红冲中、已红冲。
- 发票查验状态：待查验、查验通过、查验失败、无需查验。
- 无票使用状态：未使用、部分使用、已使用、已关闭。
- 同步状态：未同步、同步中、同步成功、同步失败。

关键规则：

- 结算单号、供应商、核算主体、结算余额、本次核销金额/本次红冲金额为核心必填。
- 发票核销单只能选择供应商与主表区一致的待到票记录；同一单据内同一结算单不可重复选择。
- 发票核销提交时，本次核销金额合计必须大于 0，且不得超过所选结算明细未到票金额。
- 发票价税合计金额合计应等于本次核销合计；Demo 可允许差异提示，但提交审批时建议阻断明显超额。
- 预付款余额大于 0 时展示预付核销区；本次预付核销金额不得超过未核销金额。
- 红冲单只能选择审批完成的发票核销记录；本次红冲金额不得大于已核销金额/结算余额。
- 无票核销时，本次核销金额不得超过结算余额；“是否已结算=否”时必须填写合同信息区。
- 审批通过后才真正更新已到票金额、已核销金额、发票余额已用金额、无票申请台账；提交审批阶段只更新占用/到票中金额。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `pendingInvoiceLedger`：待到票台账 12-20 条，覆盖发票未到、部分到票、到票中、已到票完结、已无票核销、同步失败。
- `invoiceWriteoffApplications`：发票核销单 8-12 条，覆盖草稿、审批中、财务待签收、已驳回、已完成。
- `invoiceWriteoffLedger`：发票核销台账 12-20 条，覆盖可红冲、红冲中、已红冲、部分红冲。
- `invoiceRedFlushApplications`：发票红冲单 6-10 条，覆盖草稿、审批中、财务待确认、已完成、已驳回。
- `noInvoiceApplications`：无票核销申请单 6-10 条，覆盖已结算、未结算、审批中、已完成、已驳回。
- `noInvoiceLedger`：无票核销申请台账 8-12 条，覆盖未使用、部分使用、已使用。
- `invoicePool`：发票对象 12-20 条，包含专票/普票、电票/纸票、查验通过/失败、不同税率。
- `prepaymentPool`：供应商预付款台账 6-10 条，供预付核销区选择。
- `approvalRecords`、`operationLogs`、`syncLogs`：审批、操作、查验和凭证生成记录。

样例数据要能串起来：

- 一条“双十一达人种草结算单”，待到票总额 120000 元，先做 80000 元发票核销，再展示部分到票状态。
- 一条“直播坑位费结算单”，发票核销完成后从核销台账发起 30000 元红冲，审批后回退待到票金额。
- 一条“品牌推广框架合同”供应商存在预付款余额，核销时展示预付核销区并更新是否到票。
- 一条“平台服务费结算单”允许无票核销，审批通过后进入无票核销申请台账。
- 一条发票查验失败记录，失败原因为“购方税号与核算主体不一致”，用于展示 error 状态和重新上传。

## 关键交互

- 待到票台账支持按结算单号、营销活动、供应商、费用小类、发票状态、完结状态筛选。
- 台账顶部建议展示摘要指标：待到票总额、已到票金额、未到票金额、到票中金额、允许无票金额、查验失败数。
- 待到票列表行内支持“发票核销”“无票申请”“详情”；状态为已到票完结时禁用核销入口。
- 发票核销单选择供应商后，关联待到票弹窗只显示同供应商可用记录，支持多选且防重复。
- 选择待到票记录后自动带出结算日期、营销活动、费用大类/小类、结算余额、未到票金额。
- 上传发票为 mock 行为：可从内置发票池选择或点击“模拟上传”，自动回写发票号码、代码、开票日期、价税合计、不含税金额、税额和附件。
- 发票金额变化时实时刷新本次核销合计、结算明细未到票余额、主表价税合计、不含税金额和税额。
- 存在预付款余额时显示预付核销区；无余额时收起该区并提示“当前供应商无可用预付”。
- 提交审批后生成审批记录，按钮切换为“模拟审批通过”“模拟驳回”“撤回”。
- 财务审核通过后模拟生成凭证号，例如 `KD-202605-0001`，并写入操作日志。
- 发票核销台账行内“发票红冲”打开红冲单，自动带出原核销单和发票明细；红冲金额默认等于可红冲余额，可手动调小。
- 红冲审批通过后，原核销台账红冲状态更新，待到票台账金额回退，发票对象可用余额恢复。
- 无票申请单根据“是否已结算”切换表单：已结算走待到票选择，未结算走关联合同信息区。
- 导出、发票查验、提交 OA、生成凭证、同步金蝶全部只做前端反馈和状态更新。

## 第三方系统处理方式

- 发票平台、OA、金蝶、ERP、业务中台、纸质发票签收、合同系统、付款系统全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟发票查验”：在待查验、查验通过、查验失败之间切换，并展示失败原因。
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点和待办提示。
  - “模拟财务签收”：发票核销单进入财务待确认或可生成凭证状态。
  - “模拟生成凭证”：生成业务凭证号和金蝶凭证号，状态变为已完成。
  - “模拟同步金蝶”：更新同步状态、最近同步时间、同步批次号；失败时展示失败原因和重试入口。
  - “模拟导出”：toast 提示已生成导出任务，不创建真实文件。
- 不连接真实发票查验接口，不上传真实发票文件，不调用真实 OA、金蝶、ERP、银行或税务系统。

## UI/UX 重点

- 整体按财务 B 端后台设计，突出结算单、供应商、到票/未到票金额、发票状态、审批状态和凭证号。
- 待到票台账作为模块入口，建议使用筛选区 + 摘要指标 + 表格 + 详情抽屉。
- 发票核销单字段较多，按“基础信息、结算明细、预付核销、发票信息、附件、审批记录”分区。
- 结算明细、发票信息、红冲明细使用可横向滚动表格，固定行号、结算单号、金额、状态等关键列。
- 金额统一右对齐、千分位展示；待到票总额、已到票、未到票、本次核销/红冲应能快速比较。
- 状态标签明确：草稿/未提交为默认，审批中/到票中/红冲中为处理中，已完成/查验通过为成功，已驳回/查验失败/同步失败为失败，已红冲/已关闭为禁用。
- 发票查验失败、金额超额、供应商不一致、重复选择等错误要在字段旁或表格行内直接提示。
- 附件只展示文件名、上传人、上传时间和 mock 状态，不做真实文件预览或下载。
- 空状态提供“重置筛选”或“查看全部待到票”；错误状态提供“重试查验/同步”。

## 验收标准

- 页面名称、核心字段、表单分区、弹窗选择、台账字段和台账更新关系与原始详细设计保持一致。
- 至少跑通“待到票台账 -> 发票核销单 -> 提交审批 -> 审批通过 -> 发票核销台账插入 -> 待到票状态/金额更新”的闭环。
- 至少跑通“发票核销台账 -> 发票红冲单 -> 审批通过 -> 待到票和发票余额回退”的闭环。
