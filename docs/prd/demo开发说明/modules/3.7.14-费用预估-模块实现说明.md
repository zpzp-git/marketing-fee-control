# 3.7.14 费用预估模块实现说明

本文用于指导 Gemini 和 Codex 实现“费用预估”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

费用预估模块用于承接合同、PO 执行单、投放账单、佣金账单、平台扣款和代运营业务数据，形成后续预提、摊销、对账和待到票的费用基础：

- 支持查看合同摊销、单次执行、投放、直播/佣金、平台扣款、代运营业务数据等费用预估台账。
- 支持用 mock 行为模拟“导入/同步账单 -> 标准账单转换 -> 计算折扣/佣金/摊销 -> 生成预估台账”。
- 支持对投放、直播、单次执行等预估记录发起“预提”“对账”模拟，并更新是否预提、预提金额、是否对账、对账金额、差异金额、对账结果。
- 支持合同摊销台账的中止/终止摊销模拟，展示已摊销、剩余摊销、最新摊销日期和摊销状态变化。
- 支持平台扣款费用从 OMS 资金账单解析结果生成台账，并 mock 写入待到票台账。

Demo 阶段重点跑通“来源数据 -> 预估生成 -> 预提/摊销/对账状态更新 -> 下游台账可查看”的闭环，不接真实 OMS、影刀、达人系统、合同系统、数仓、ERP 或发票系统。

## Demo 业务闭环

优先实现 5 条可演示闭环：

1. 合同摊销闭环：从 mock 合同结构化信息选择一条“需要摊销”的生效合同 -> 模拟财务复核摊销规则 -> 生成合同摊销费用台账 -> 按日摊销金额自动计算已摊销金额和剩余摊销金额 -> 点击中止/终止摊销后状态变化并记录原因。
2. 投放费用预估闭环：模拟 RPA/手工导入投放账单 -> 标准账单转换成功 -> 按投放账号、营销活动、店铺/品牌/渠道汇总 -> 计算现金消耗、折扣率、预估费用 -> 写入投放费用预估台账，初始是否预提=否、是否供应商对账=否。
3. 直播/佣金费用预估闭环：模拟导入达人/直播佣金账单 -> 匹配达人 ID、合同编号和佣金比例 -> 汇总线上佣金、线下佣金、直播坑位费 -> 写入直播费用预估台账 -> 发起预提后回写预提单号和预提金额。
4. 单次执行费用预估闭环：从合同 PO 执行单或达人 PO 执行单生成单次执行费用预估台账 -> 自动带出合同、任务 ID、下单金额、合同折扣、预估费用和预算维度 -> 发起对账后展示对账金额、差异金额和差异原因。
5. 平台扣款费用闭环：模拟 OMS 推送资金账单解析结果 -> 命中费用小类、预算科目、供应商映射 -> 生成平台扣款费用台账 -> 对“有票/需跟踪发票”的费用模拟插入待到票台账。

可选演示闭环：

- 代运营数据：从得物销售额、快手/抖音退前 GMV 数据生成单次执行或直播预估记录。
- 转换失败处理：账单转换失败时展示问题记录，如投放计划未匹配、达人 ID 缺失、费用小类未配置，业务调整后重新生成。
- 对账差异处理：对账金额与预估费用不一致时标记“有差异”，填写差异原因，生成对账结算单单据编号。

跨模块数据只做 mock 串联：

- 合同、合同结构化、合同 PO、达人 PO、直播 PO 来自营销合同管理 mock。
- 投放账户、店铺、费用小类、预算科目、营销活动来自基础数据和预算管理 mock。
- 预提单、对账结算单、待到票台账只做本地状态模拟，供费用对账结算和发票管理页面展示。

- 代运营/直播场景：渠道、业务来源、直播间名称、直播间 ID、付款日期、退前 GMV、营销活动计划分类、营销活动、预算部门、预算科目、费用小类、店铺、品牌、合同编号、供应商。
- 得物场景：渠道、业务来源、发货日期、实收收入、营销活动计划分类、营销活动、预算部门、预算科目、费用小类、店铺、品牌、合同编号、供应商。

状态枚举：

- 生成状态：未生成、生成中、生成成功、生成失败、待调整、已重新生成。
- 预提状态：未预提、预提中、已预提、无需预提、预提失败。
- 对账状态：未对账、对账中、已对账、差异待处理、已关闭。
- 对账结果：一致、有差异、待确认。
- 摊销状态：待摊销、摊销中、已摊销完毕、已中止、已终止。
- 入账状态：未入账、入账中、已入账、入账失败。
- 同步状态：未同步、同步中、同步成功、同步失败。

关键规则：

- 预估费用、支出金额、预提金额、对账金额必须大于等于 0；涉及冲回或退款的样例允许负数，但需标明业务场景。
- 投放预估费用建议按 `现金消耗 * 折扣率` 计算，允许手动调整后形成“调整后预估费用”。
- 直播预估费用建议按 `线上佣金 + 线下佣金 + 直播坑位费` 计算；线下佣金可按订单实付金额和线下佣金比例模拟计算。
- 单次执行预估费用建议按 `下单金额 * 合同折扣` 计算。
- 对账差异金额=`对账金额 - 预估费用或调整后预估费用`；差异不为 0 时对账结果为“有差异”并要求填写差异原因。
- 发起预提后回写是否预提、预提金额和预提单号；已预提记录不允许重复预提，只允许查看或撤销模拟。
- 平台扣款解析失败时不生成待到票台账，必须展示数据问题记录和“重新匹配规则”入口。

## 关键交互

- 费用预估工作台顶部展示摘要指标：本月预估费用、已预提金额、待预提金额、已对账金额、差异金额、同步/转换失败数。
- 各台账支持按合同编号、供应商、核算主体、费用日期、营销活动、预算科目、费用小类、预提状态、对账状态筛选。
- 台账行内支持“详情”“预提”“对账”“查看来源”“导出模拟”；不满足条件的操作置灰并提示原因。
- “模拟导入账单”打开抽屉或弹窗，选择账单类型、期间、平台，点击生成后插入对应预估台账和操作日志。
- 转换结果抽屉分为“来源明细、汇总结果、规则命中、异常问题、操作记录”，方便演示从来源到台账的链路。
- 对账弹窗自动带出预估费用，允许输入对账日期、对账金额、差异原因；保存后更新对账状态和差异金额。
- 预提操作可批量选择未预提记录，生成 mock 预提单号，例如 `YT-202605-0012`，并回写预提金额。
- 合同摊销台账点击“中止摊销/终止摊销”需填写原因，确认后更新摊销状态和操作日志。
- 平台扣款“模拟同步 OMS”可在成功、失败、部分失败之间切换；失败时展示数据问题记录和重试入口。
- 导出、同步、生成预提单、生成待到票、推送对账结算全部只做前端反馈和状态更新。

## 第三方系统处理方式

- 合同系统、达人系统、影刀/RPA、OMS、数仓、ERP、金蝶、发票系统、广告平台、电商平台全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟同步合同结构化”：生成合同摊销候选数据。
  - “模拟导入 RPA 账单”：生成标准业务账单明细和导入批次号。
  - “模拟标准账单转换”：切换转换成功/失败，失败时写入问题记录。
  - “模拟计算折扣/佣金/摊销”：按 mock 规则计算预估费用或日摊销金额。
  - “模拟同步 OMS”：生成平台扣款台账或同步失败原因。
  - “模拟生成预提单/待到票”：生成单号并回写状态，不调用真实下游。
  - “模拟导出”：toast 提示已生成导出任务，不创建真实文件。
- 不连接真实 OMS、影刀、达人系统、合同系统、数仓、ERP、金蝶、广告平台或电商平台，不上传真实账单文件。

## UI/UX 重点

- 整体按财务 B 端后台设计，突出费用日期、合同/供应商、费用小类、预算科目、预估费用、预提状态、对账状态和差异金额。
- 工作台作为入口，使用摘要指标 + 待处理列表 + 异常列表，帮助演示人员快速进入生成、预提、对账、异常处理。
- 台账页面信息密度可以较高，但要固定关键列：单据编号、合同编号/投放账号/达人昵称、供应商、预估费用、状态、操作。
- 金额统一右对齐、千分位展示；预估费用、调整后预估费用、对账金额、差异金额用同一视觉规则便于比较。
- 状态标签明确：未生成/未预提/未对账为默认，生成中/预提中/对账中/摊销中为处理中，已生成/已预提/已对账为成功，生成失败/同步失败/有差异为警示或失败。
- 对字段很多的台账使用列配置或“更多字段”抽屉，不要把所有规则字段挤在首屏。
- 转换失败、规则未命中、达人 ID 缺失、预算科目缺失、供应商不一致等错误要在行内或抽屉中直接说明。
- 平台扣款规则只展示命中的核心规则和异常说明，不展示完整规则清单大表。
- 空状态提供“模拟导入账单”“重置筛选”；错误状态提供“重新转换”“重新同步”“查看问题记录”。

## 验收标准

- 页面名称、核心字段、台账列、查询字段和生成路径与原始详细设计保持一致。
- 至少跑通“合同结构化信息 -> 财务确认摊销 -> 合同摊销费用台账生成 -> 中止/终止摊销”的闭环。
- 至少跑通“投放账单导入 -> 标准账单转换 -> 投放费用预估台账生成 -> 预提/对账状态更新”的闭环。
- 至少跑通“佣金/直播账单导入 -> 计算佣金比例 -> 直播费用预估台账生成 -> 预提单号回写”的闭环。
- 至少跑通“合同 PO/达人 PO -> 单次执行费用预估台账 -> 对账差异展示”的闭环。
- 至少跑通“OMS 资金账单解析 -> 平台扣款费用台账 -> mock 生成待到票”的闭环。
- 台账可按合同编号、供应商、费用日期、费用小类、营销活动、预提状态、对账状态筛选，支持重置、详情查看和导出模拟。
- 预提、对账、生成、同步失败、重新生成、中止摊销等状态均可前端模拟并有操作日志。
- 计算规则可被演示人员看懂：投放折扣、直播佣金、单次执行折扣、合同日摊销、对账差异至少有可见口径。
- 外部系统行为全部为 mock，不发生真实 OMS、RPA、达人系统、合同系统、数仓、ERP、金蝶、广告平台、电商平台或附件上传调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
