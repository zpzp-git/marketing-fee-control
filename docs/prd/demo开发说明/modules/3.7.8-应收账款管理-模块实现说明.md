# 3.7.8 应收账款管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“应收账款管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

应收账款管理模块用于展示营销相关应收账款确认、收款核销、坏账计提、单项坏账确认和坏账收回的前端演示闭环：

- 支持查看应收账款台账，展示客户、核算主体、应收金额、已收金额、余额、账龄、坏账准备和核销状态。
- 支持发起通用坏账计提申请，按客户和账龄填写应收余额、计提比例，自动计算本期计提金额和本期补计提金额。
- 支持发起单项坏账申请，按处理类型演示坏账申请、坏账确认、坏账收回三类场景。
- 支持提交审批、审批通过/驳回、生成凭证、回写金蝶凭证号等状态变化。
- 支持审批通过后更新应收账款台账中的坏账准备、坏账确认金额、坏账收回金额和应收余额。

Demo 阶段重点是跑通“查看应收账款 -> 发起坏账计提/单项坏账 -> 审批 -> 模拟生成凭证 -> 更新应收和坏账金额”的闭环，不做真实 OA、金蝶、ERP、银行收款或第三方系统集成。

原始资料中有两点需要在 Demo 中统一口径：

- `通用坏账计提单据.md` 中“本期补计提金额”表格公式出现“上期计提金额-本期计提金额”，主表又写“计提金额合计=本期补计提金额合计”。Demo 建议统一为更符合演示直觉的口径：本期补计提金额 = 本期计提金额 - 上期计提金额，可为负数时表示冲回；如果实现想严格贴原文，也需在页面提示中说明。

## 页面清单

| 页面 | Demo 定位 | 主要操作 |
|---|---|---|
| 应收账款台账 | 模块入口和余额主台账 | 查询、重置、导出模拟、查看详情、发起通用坏账计提、发起单项坏账、模拟收款核销 |
| 应收账款确认单 | 根据流程图合理补齐的应收确认单据 | 新增、保存草稿、提交审批、审批通过后生成应收台账 |
| 收款/核销单 | 根据流程图合理补齐的收款或核销单据 | 选择应收记录、填写收款金额或核销金额、提交审批、审批通过后更新余额 |
| 通用坏账计提单 | 原始设计核心单据 | 新增、填写账龄明细、自动计算计提金额、提交审批、生成计提凭证、回写凭证号 |
| 单项坏账申请单 | 原始设计核心单据 | 选择处理类型、填写单项客户坏账明细、提交 OA mock 审批、生成凭证、更新台账 |
| 坏账处理台账 | 建议补齐的坏账过程台账 | 查看计提、确认、收回记录，按客户和单据状态筛选 |

## Demo 业务闭环

优先实现 3 条可演示闭环：

1. 应收确认和收款闭环：业务人员新建应收账款确认单 -> 填写客户、核算主体、合同/事项、应收金额和到期日 -> 提交审批 -> 审批通过后生成应收账款台账 -> 财务发起收款/核销单 -> 审批通过后更新已收金额和应收余额。
2. 通用坏账计提闭环：财务从应收账款台账选择多条客户应收 -> 发起通用坏账计提单 -> 按账龄填写 1 年以内、1-2 年、2-3 年、3-4 年、4 年以上金额和计提比例 -> 自动计算各账龄计提金额、本期计提金额、本期补计提金额和计提金额合计 -> 审批通过 -> 模拟生成计提凭证和金蝶凭证号 -> 回写台账坏账准备金额。
3. 单项坏账处理闭环：财务从台账选择一条风险客户 -> 发起单项坏账申请单 -> 选择处理类型“坏账申请/坏账确认/坏账收回” -> 系统按处理类型显示对应金额字段并计算金额合计 -> 提交 OA mock 审批 -> 审批通过后生成凭证 -> 更新坏账处理台账和应收账款台账。

跨模块数据只做 mock 串联：

- 客户、核算主体、合同、营销事项可复用基础数据、销售合同或营销事项的 mock 对象名称。
- 收款来源、ERP 凭证、OA 审批、金蝶凭证全部使用前端状态模拟。
- 台账金额更新只需在当前模块内闭环，不要求与销售合同、发票、付款等模块做真实一致性校验。

## 主要字段建议

通用单据字段：

- 单据编号、单据名称、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 核算主体、凭证号、说明、附件名称。
- 单据状态：草稿、审批中、已驳回、审批通过、凭证生成中、凭证生成失败、已完成。
- 审批信息：行号、流程环节名称、审批人、审批日期、审批意见。
- 同步信息：来源系统、同步状态、最近同步时间、同步批次号、失败原因。

应收账款台账字段：

- 应收编号、客户名称、核算主体、来源单据、来源业务类型、合同编号/事项编号。
- 应收总额、已收金额、核销金额、应收余额、坏账准备余额、坏账确认金额、坏账收回金额。
- 账龄：1 年以内、1 年至 2 年、2 年至 3 年、3 年至 4 年、4 年以上。
- 到期日、逾期天数、账龄区间、风险等级、催收状态、最后收款日期。
- 状态建议：未收款、部分收款、已收清、计提中、已计提、核销中、已核销、坏账收回中、已关闭。

应收账款确认单字段：

- 主表区：核算主体、客户名称、来源业务类型、合同编号/营销事项编号、币种、应收金额、预计收款日期、说明。
- 明细区：行号、费用/收入项目、业务日期、应收金额、税率、含税金额、备注。
- 关键规则：客户、核算主体、应收金额、预计收款日期必填；应收金额必须大于 0；审批通过后生成或更新应收账款台账。

收款/核销单字段：

- 主表区：核算主体、客户名称、处理类型、收款日期、收款金额、核销金额、说明。
- 应收明细：行号、应收编号、应收总额、已收金额、应收余额、本次收款金额、本次核销金额、剩余余额。
- 关键规则：本次收款金额或核销金额必须大于 0；本次处理金额不能超过应收余额；审批通过后更新应收余额。

通用坏账计提单字段：

- 主表区：申请日期、申请人、申请人公司、申请人部门、申请人岗位、核算主体、计提金额合计、凭证号、说明。
- 申请明细区：行号、客户、应收总额、1 年以内、1 年以内计提比例、1 年以内计提金额、1 年至 2 年、1 年至 2 年计提比例、1 年至 2 年计提金额、2 年至 3 年、2 年至 3 年计提比例、2 年至 3 年计提金额、3 年至 4 年、3 年至 4 年计提比例、3 年至 4 年计提金额、4 年以上、4 年以上计提比例、4 年以上计提金额、上期计提金额、本期计提金额、本期补计提金额。
- 关键规则：客户、应收总额、上期计提金额必填；各账龄计提金额=账龄金额*计提比例；本期计提金额=各账龄计提金额合计；计提金额合计=本期补计提金额合计；凭证号审批通过并模拟生成凭证后回写。

单项坏账申请单字段：

- 主表区：申请日期、申请人、申请人公司、申请人部门、申请人岗位、核算主体、处理类型、金额合计、凭证号、说明。
- 处理类型：坏账申请、坏账确认、坏账收回。
- 计提明细信息：行号、客户、应收总额、上期计提金额、本期计提金额、本期补计提金额、本期坏账确认金额、本期坏账收回金额。
- 显隐规则：处理类型=坏账申请，重点展示上期计提金额、本期计提金额、本期补计提金额；处理类型=坏账确认，重点展示本期坏账确认金额；处理类型=坏账收回，重点展示本期坏账收回金额。
- 金额合计规则：坏账申请=本期补计提金额合计；坏账确认=本期坏账确认金额合计；坏账收回=本期坏账收回金额合计。
- 关键规则：核算主体、处理类型、客户、应收总额、说明必填；坏账确认金额不能超过应收余额；坏账收回金额不能超过已确认坏账金额。

坏账处理台账字段：

- 处理编号、来源单据号、处理类型、客户名称、核算主体、应收总额、处理金额、上期计提金额、本期计提金额、本期补计提金额、坏账确认金额、坏账收回金额、凭证号、审批状态、处理日期、经办人、同步状态。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `receivableLedger`：应收账款台账 12-20 条，覆盖未收款、部分收款、已收清、已计提、已核销、坏账收回中、逾期风险。
- `receivableConfirmations`：应收账款确认单 8-12 条，覆盖草稿、审批中、已驳回、已完成。
- `receiptWriteOffApplications`：收款/核销单 8-12 条，覆盖收款、核销、部分核销、审批驳回。
- `generalBadDebtAccrualApplications`：通用坏账计提单 8-12 条，覆盖草稿、审批中、已驳回、凭证生成失败、已完成。
- `specificBadDebtApplications`：单项坏账申请单 8-12 条，覆盖坏账申请、坏账确认、坏账收回三种处理类型。
- `badDebtLedger`：坏账处理台账 12-20 条，能关联通用计提单和单项坏账申请单。
- `customerOptions`：客户 mock 10-20 条，包含客户名称、客户编码、所属渠道、风险等级、默认核算主体。
- `accountingEntityOptions`：核算主体 mock，至少包含 3-5 个主体。
- `approvalRecords`：审批记录 mock，包含业务审批、财务审批、财务负责人、审批日期和审批意见。
- `voucherRecords`：凭证记录 mock，包含业财中台凭证号、金蝶凭证号、凭证状态、失败原因。

样例数据要能串起来：

- 一条客户应收 120000 元，已收 40000 元，余额 80000 元，可发起通用坏账计提。
- 一条账龄跨 1 年以内、1-2 年、2-3 年的客户应收，可演示计提比例和金额自动计算。
- 一条单项坏账确认客户，应收余额等于坏账确认金额，审批后台账状态变为已核销。
- 一条坏账收回记录，已确认坏账 30000 元，本期收回 10000 元，审批后回写坏账收回金额。
- 一条凭证生成失败记录，展示失败原因和“模拟重试生成凭证”入口。
- 一条审批驳回记录，单据可重新编辑并再次提交。

## 关键交互

- 列表页统一支持查询、重置、分页、导出模拟、详情抽屉。
- 应收账款台账支持按客户、核算主体、账龄区间、风险等级、状态、逾期天数筛选。
- 台账行内支持“详情”“发起计提”“单项坏账”“模拟收款核销”；已收清或已关闭记录禁用不适用操作。
- 应收账款确认单支持保存草稿、提交审批、审批通过、审批驳回；审批通过后新增应收账款台账记录。
- 收款/核销单从台账带出客户、核算主体和应收余额；提交时校验本次处理金额不能超过余额；审批通过后更新已收金额、核销金额和应收余额。
- 通用坏账计提单支持从台账批量选择客户，也支持手工新增明细行。
- 账龄金额和计提比例变化时，实时计算各账龄计提金额、本期计提金额、本期补计提金额和主表计提金额合计。
- 通用坏账计提单提交时校验应收总额是否等于各账龄金额合计；不相等时给出明确提示，Demo 可允许保存草稿但不允许提交。
- 单项坏账申请单选择处理类型后动态显示重点字段，并保持表格列宽稳定。
- 单项坏账申请单的金额合计随处理类型自动取对应明细金额合计。
- 提交审批后单据状态变为审批中，生成审批记录；审批驳回后状态变为已驳回，可编辑后重新提交。
- 审批通过后展示“模拟生成凭证”或自动进入凭证生成中；成功后回写业财中台凭证号、金蝶凭证号和最近同步时间。
- 凭证生成失败时保留单据状态，展示失败原因和“重试生成凭证”入口。
- 应收详情建议展示基础信息、账龄分布、收款/核销记录、坏账计提记录、单项坏账记录、凭证记录和审批记录。

## 第三方系统处理方式

- OA 审批、金蝶凭证、ERP 应收、银行收款、客户对账、附件上传全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换审批状态，记录审批人、审批日期和意见。
  - “模拟生成业财凭证”：单据进入凭证生成中，成功后生成业财凭证号。
  - “模拟同步金蝶”：生成金蝶凭证号，更新同步状态和最近同步时间。
  - “模拟同步失败”：同步状态变为失败，展示失败原因，可重试。
  - “模拟银行收款”：为收款/核销单生成收款流水号，只影响 mock 台账。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不连接真实 OA、金蝶、ERP、银行、客户系统，不上传或解析真实附件。

## UI/UX 重点

- 整体按财务 B 端后台设计，重点突出客户、核算主体、账龄、应收余额、坏账准备和凭证状态。
- 应收账款台账是模块入口，建议顶部放金额摘要：应收总额、应收余额、逾期金额、坏账准备余额、本期计提金额。
- 金额统一右对齐、千分位展示；负数补计提金额可用冲回样式或提示说明。
- 账龄分布建议用横向明细列或详情中的小型分布条展示，避免列表过宽时核心列被淹没。
- 状态色明确：草稿为默认，审批中/凭证生成中为处理中，已完成/已收清为成功，已驳回/同步失败为失败，逾期/高风险为警示。
- 单据页使用分组区块：基础信息、应收/计提明细、附件模拟、审批信息、凭证信息、操作记录。
- 通用坏账计提单明细列较多，建议支持横向滚动，并固定客户、应收总额、本期计提金额、本期补计提金额等关键列。
- 单项坏账申请单的处理类型应放在靠前位置，切换后通过字段显隐或列高亮帮助演示差异。
- 详情抽屉要能解释金额变化来源，避免只展示最终余额。
- 空状态提供“新建应收确认单”或“重置筛选”；错误状态提供“重试模拟同步”。
- 附件只展示文件名、上传人、上传时间和 mock 上传状态，不做真实文件解析。

## 验收标准

- 页面名称、核心字段、表单分区、处理类型、审批区和凭证回写流程与原始详细设计保持一致。
- 至少跑通“应收账款台账 -> 通用坏账计提 -> 审批通过 -> 生成凭证 -> 台账坏账准备更新”的闭环。
- 至少跑通“应收账款台账 -> 单项坏账申请 -> 审批通过 -> 生成凭证 -> 台账坏账确认/收回金额更新”的闭环。
- 应收账款确认单和收款/核销单作为流程图补齐页面，能完成应收生成和余额更新演示。
- 通用坏账计提单能按账龄和计提比例自动计算各账龄计提金额、本期计提金额、本期补计提金额和计提金额合计。
- 单项坏账申请单能按处理类型切换字段重点，并正确计算金额合计。
