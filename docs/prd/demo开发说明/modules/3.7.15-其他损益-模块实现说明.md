# 3.7.15 其他损益模块实现说明

本文用于指导 Gemini 和 Codex 实现“其他损益”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

其他损益模块用于承接常规营销费用之外的损益、预提、内部交易和物流结算业务，形成可查询、可审批、可回写台账的 Demo 闭环：

- 支持其他损益确认单审批通过后生成其他损益台账。
- 支持会员积分、预计退货、渠道折扣等预提/计提单据审批后写入其他损益预提台账。
- 支持预计退货按店铺收入和预计退货率自动计算预计退货金额。
- 支持内部交易结算单按“服务类”和“会员积分”两类展示不同明细，并更新内部交易信息台账或会员积分使用状态。
- 支持物流费用结算单审批后，根据是否后续付款/跟票，mock 写入待到票或其他损益预提台账。
- 支持各台账查询、详情、导出模拟、冲销/入账状态变化。

Demo 阶段重点跑通“来源数据 -> 单据生成/填写 -> 提交审批 -> 审批通过 -> 台账回写/状态更新”的闭环，不接真实 OMS、ECRP、有赞、OA、金蝶、ERP、物流系统或发票系统。

## Demo 业务闭环

优先实现 5 条可演示闭环：

1. 其他损益确认闭环：新建其他损益确认单 -> 自动带出申请人、申请日期、申请组织 -> 选择或生成一条资金流水 -> 维护借贷记账明细和核算维度 -> 校验借方合计=贷方合计 -> 提交审批 -> 审批通过后生成凭证号并插入其他损益台账。
2. 会员积分预提闭环：模拟从 ECRP/会员系统同步店铺积分余额 -> 按积分兑换率、积分兑换汇率计算积分价值和预提金额 -> 提交会员积分预提单 -> 审批通过后写入其他损益预提台账，业务类型=会员积分，预提状态=已预提。
3. 预计退货预提闭环：模拟 OMS 推送店铺入账收入 -> 从预计退货率台账带出当月退货率 -> 自动计算预计退货金额=收入*预计退货率 -> 提交预计退货预提单 -> 审批通过后写入其他损益预提台账，业务类型=预计退货，经分科目=预计负债预提。
4. 内部交易结算闭环：从内部交易信息台账选择“服务类”或“会员积分”记录 -> 生成内部交易结算单 -> 服务类按收入金额*服务费比例计算服务费金额；会员积分校验未入账记录才可提交 -> 审批通过后生成凭证号，更新内部交易信息台账是否入账和入账金额。
5. 渠道折扣/物流结算闭环：渠道折扣计提单按成交 GMV*计提比例写入其他损益预提台账；物流费用结算单审批通过后，根据 mock 标记“是否跟进发票/是否会做付款”，写入待到票台账或其他损益预提台账。

可选演示闭环：

- 预提冲销：从其他损益预提台账选择一条已预提、未冲销记录 -> 填写冲销月份和冲销原因 -> 生成冲销单号/冲销凭证号 -> 原记录冲销状态变为已冲销。
- 审批驳回：审批中单据被驳回后回到可编辑状态，不写入台账；已生成的 mock 占用或入账状态要释放。
- 同步失败处理：OMS/ECRP/有赞/物流账单同步失败时展示失败原因，允许“重新同步”只更新前端状态。

跨模块数据只做 mock 串联：

- 店铺、渠道、品牌、核算主体、供应商、客户、部门等来自基础数据 mock。
- 店铺收入来自 OMS 入账收入 mock。
- 会员积分余额来自 ECRP/会员系统 mock。
- 有赞服务类收入、会员积分使用汇总来自内部交易 mock。
- 待到票台账、凭证号、发票跟踪只做本地状态模拟，供发票管理或费用对账结算页面展示。

## 主要字段建议

通用单据主表字段：

- 单据编号、申请日期、申请人、申请人公司、申请人部门、申请人岗位、核算主体、凭证号、说明、单据状态、审批状态。
- 附件区只做 mock 附件名称，不做真实上传。
- 审批区展示流程环节名称、审批人、审批日期、审批意见。

其他损益确认单：

- 主表：记账日期、核算主体、凭证号、结算总金额、借方合计、贷方合计、说明。
- 流水信息区：流水编号、对方公司、流水金额、交易日期、流水备注。
- 对账明细区：借方/贷方、记账码、核算科目、现金流项目、辅助核算项、记账金额、备注。
- 核算维度：供应商、部门、品牌、渠道、店铺、客户、费用分摊事业线、员工。
- 关键校验：借方合计必须等于贷方合计；流水金额与结算总金额需一致或给出差异提示。

其他损益台账：

- 单据编号、核算主体、流水编号、对方公司、流水金额、交易日期、来源单据号、凭证号、入账状态。
- 查询字段：核算主体、对方公司、交易日期、入账状态。

会员积分预提单：

- 主表：核算主体、凭证号、预提总金额、预提月份、说明。
- 积分信息区：店铺、渠道、积分余额、积分兑换率、积分兑换汇率、积分价值、预提金额。
- 计算口径：积分价值=积分余额*积分兑换率；预提金额=积分价值*积分兑换汇率。

预计退货预提单：

- 主表：核算主体、凭证号、预提总金额、预提月份、说明。
- 预计退货信息区：店铺、收入、预计退货率、预计退货金额。
- 计算口径：预计退货金额=收入*预计退货率；收入只展示 OMS 已推金蝶入账收入的 mock 口径。

渠道折扣计提单：

- 主表：核算主体、凭证号、计提总金额、说明。
- 计提明细区：店铺、渠道、客户、成交 GMV、计提比例、计提金额。
- 计算口径：计提金额=成交 GMV*计提比例。

其他损益预提台账：

- 单据编号、预提月份、业务类型、核算主体、预提凭证号、预提金额、预提状态、冲销状态、经分科目、店铺、渠道、品牌、来源单据号。
- 业务类型建议：会员积分、预计退货、渠道折扣、物流费用、其他。
- 状态建议：未预提、审批中、已预提、预提失败、已冲销、部分冲销。

内部交易结算单：

- 主表：内部交易结算类型、核算主体、凭证号、合同编号、说明。
- 服务类明细：关联交易、交易月份、收入金额、服务费比例、代运营主体、受托代运营主体、服务费金额。
- 会员积分明细：关联积分使用信息、交易月份、店铺、店铺结算主体、积分使用金额、积分换算后金额。
- 关键校验：会员积分来源记录若是否入账=是，禁止提交并提示“此笔积分使用已入账，请核对”。

内部交易信息台账：

- 服务类：内部交易类型、交易月份、收入金额、服务费比例、代运营主体、受托代运营主体、服务费金额、是否入账。
- 会员积分：内部交易类型、交易月份、店铺、店铺结算主体、积分使用、积分换算后金额、是否入账。

店铺收入台账与预计退货率台账：

- 店铺收入台账：日期、核算主体、店铺、收入、来源系统、同步状态、最近同步时间。
- 预计退货率台账：店铺、1月-12月预计退货率、导入批次、更新人、更新时间。

物流费用结算单：

- 主表：核算主体、凭证号、开票金额合计/金额合计、说明、是否跟进发票、是否会做付款。
- 物流费用信息区：仓库、发货物流、项、运单数量、金额、备注、快递名称、货主、含税金额、事业线。
- 审批通过后：需要跟票则 mock 生成待到票记录；无需付款或仅预提则写入其他损益预提台账。

## 关键交互

- 工作台顶部展示摘要指标：本月其他损益金额、本月预提金额、待审批、待冲销、待入账、同步失败。
- 所有台账支持查询、重置、详情、导出模拟；核心筛选包含核算主体、月份、业务类型、店铺、渠道、状态。
- 单据表单按“主表信息 + 明细区 + 附件模拟 + 审批信息”分区，金额合计实时计算。
- 会员积分、预计退货、渠道折扣、物流费用明细支持行新增/删除，金额字段统一右对齐并千分位展示。
- “模拟同步 OMS/ECRP/有赞”打开抽屉，展示来源系统、同步批次、最近同步时间、成功/失败条数和失败原因。
- “生成预提单/自动填充明细”只从内置 mock 数据生成记录，不上传真实文件。
- 提交审批后状态从草稿变为审批中；审批通过后生成凭证号，写入对应台账；审批驳回后允许编辑重提。
- 预提台账“冲销”操作需填写冲销月份、冲销原因，确认后更新冲销状态和冲销凭证号。
- 内部交易结算类型切换时，服务类只展示有赞交易信息，会员积分只展示会员积分信息。
- 物流费用结算审批通过后弹出结果反馈：已生成待到票记录或已生成其他损益预提记录。

## 第三方系统处理方式

- OMS、ECRP/会员系统、有赞、OA、金蝶、ERP、物流系统、发票系统全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作日志：
  - “模拟同步 OMS 收入”：生成店铺收入台账或同步失败原因。
  - “模拟同步 ECRP 积分”：生成积分余额明细和同步批次号。
  - “模拟同步有赞交易”：生成服务类内部交易信息。
  - “模拟推送 OA 审批”：新增审批记录并切换审批状态。
  - “模拟生成金蝶凭证”：生成 `PZ-YYYYMM-####` 凭证号并回写单据。
  - “模拟生成待到票”：生成待到票单号，不调用真实发票系统。
  - “模拟导出”：toast 提示已生成导出任务，不创建真实文件。
- 不连接真实外部接口，不使用真实账号、密钥、账单文件或附件上传。

## UI/UX 重点

- 整体按财务 B 端后台设计，突出月份、核算主体、店铺、渠道、业务类型、金额、预提/冲销/入账状态。
- 工作台使用摘要指标 + 待处理单据 + 同步异常列表，方便演示人员快速进入闭环。
- 台账信息密度可以较高，但首屏固定关键列：单据编号、月份/日期、业务类型、店铺/对方公司、金额、状态、操作。
- 表单字段较多时使用分组和明细表，核算维度可放在抽屉或可展开区域，不要挤在首屏。
- 金额统一右对齐、千分位展示；预提金额、计提金额、预计退货金额、服务费金额使用同一视觉规则。
- 状态标签明确：草稿/未预提为默认，审批中/同步中为处理中，已审批/已预提/已入账为成功，已驳回/同步失败/入账失败为警示或失败。
- 空状态提供“新增单据”“模拟同步”；错误状态提供“重新同步”“查看失败原因”。
- 所有自动计算字段旁边可显示简短计算口径，帮助演示人员解释结果。

## 验收标准

- 页面名称、核心字段、台账列、查询字段和台账回写规则与原始详细设计保持一致。
- 至少跑通“其他损益确认单 -> 审批通过 -> 凭证号生成 -> 其他损益台账更新”的闭环。
- 至少跑通“会员积分同步 -> 会员积分预提单 -> 审批通过 -> 其他损益预提台账更新”的闭环。
- 至少跑通“店铺收入 + 预计退货率 -> 预计退货预提单 -> 其他损益预提台账更新”的闭环。
- 至少跑通“内部交易信息台账 -> 内部交易结算单 -> 审批通过 -> 入账状态更新”的闭环。
- 至少跑通“渠道折扣计提或物流费用结算 -> 审批通过 -> 预提台账/待到票 mock 更新”的闭环。
- 台账可查询、重置、查看详情、导出模拟；单据可新增、提交、审批通过、驳回。
- 关键校验可用：借贷平衡、金额大于 0、预计退货金额计算、计提金额计算、会员积分已入账禁止重复提交。
- 第三方系统行为全部为 mock，不发生真实 OMS、ECRP、有赞、OA、金蝶、ERP、物流或发票系统调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合 B 端后台现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
