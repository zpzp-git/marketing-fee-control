# 3.7.4 保证金管理模块实现说明

本文用于指导 Gemini 和 Codex 实现“保证金管理”模块 Demo。不要按正式 PRD 重写，优先做出能演示、能闭环、能跑通的前端 mock 页面。

## 模块目标

保证金管理模块用于处理营销相关保证金的付款申请、退回申请和台账查询：

- 支持业务人员提交保证金付款申请，按保证金类型填写店铺、投放账户、合同、供应商、客户、付款链接、付款信息等。
- 支持付款申请审批通过后，模拟付款成功，并生成或更新保证金台账。
- 支持从保证金台账发起退回申请，选择可退回保证金明细，填写申请退回金额。
- 支持退回申请提交时占用保证金余额，审批通过和财务确认到账后更新已退回金额、保证金余额和是否全部退回。
- 支持平台类和非平台类保证金台账查询、导出模拟、详情查看和发起退回。

Demo 阶段重点是跑通“保证金付款申请 -> 审批通过/模拟付款 -> 保证金台账生成 -> 退回申请 -> 财务确认到账 -> 台账关闭”的闭环，不做真实付款、真实收款、真实凭证和真实第三方系统集成。

## 页面清单

| 页面 | Demo 定位 | 主要操作 |
|---|---|---|
| 保证金付款申请单 | 保证金付款单据 | 新增、按保证金类型动态显示字段、填写付款信息、保存草稿、提交审批、审批通过、模拟付款成功/失败、生成保证金台账 |
| 保证金退回申请单 | 保证金退回单据 | 新增、选择保证金台账明细、填写申请退回金额、提交审批、审批通过、财务确认到账、生成收款凭证、更新台账余额 |
| 保证金台账 | 保证金余额和退回状态台账 | 查询、重置、导出模拟、查看详情、发起退回、查看来源付款单和退回记录 |
| 关联保证金台账弹窗 | 退回申请选择台账记录 | 按投放账号、店铺筛选，可多选，同一单据内不可重复选择 |

## Demo 业务闭环

优先实现 2 条可演示闭环：

1. 平台类保证金闭环：保证金付款申请单 -> 选择店铺保证金或营销推广保证金 -> 填写店铺/三方账户或投放平台/投放账户、付款链接和付款金额 -> 提交审批 -> 审批通过 -> 模拟付款成功 -> 保证金台账新增记录 -> 从台账发起退回申请 -> 选择保证金明细并填写退回金额 -> 提交审批时占用余额 -> 审批通过并财务确认到账 -> 已退回金额增加，余额减少，余额为 0 时标记已全部退回。
2. 非平台类保证金闭环：保证金付款申请单 -> 选择合同保证金或招投标保证金 -> 填写关联合同/供应商/客户或说明附件、付款信息明细 -> 提交审批 -> 模拟付款成功 -> 生成非平台类保证金台账 -> 在台账中查看合同编号、供应商、客户、保证金总额和退回状态。

原始台账插入规则明确写到“店铺保证金和营销推广保证金”审批结束插入保证金台账；Demo 为了让非平台类台账也可演示，建议保守补齐合同保证金、付招投标保证金、退招投标保证金的台账生成逻辑，但只作为 mock 状态更新，不扩展真实付款系统。

## 主要字段建议

通用单据字段：

- 单据编号、单据名称、申请日期、申请人、申请人公司、申请人部门、申请人岗位。
- 核算主体、保证金类型、凭证号、说明、附件名称。
- 单据状态：草稿、审批中、已驳回、审批通过、付款中、付款成功、付款失败、退回中、已完成。
- 审批信息：流程环节名称、审批人、审批日期、审批意见。

保证金付款申请单字段：

- 主表区：核算主体、保证金类型、关联合同、供应商、客户、投放平台、投放账户、三方账户、店铺、预计退回日期、付款链接、付款金额、说明。
- 付款信息：行号、摘要、付款金额、付款方式、期望付款日期、收款方、付款方、付款类型、支付方式。
- 关键规则：申请日期和申请人自动带出；核算主体必填；保证金类型必填；付款金额必须大于 0。
- 类型规则：合同保证金显示并要求关联合同，带出供应商/客户；店铺保证金显示并要求三方账户、店铺、付款链接、付款金额；营销推广保证金显示并要求投放平台、投放账户、预计退回日期、付款链接、付款金额；付招投标保证金和退招投标保证金显示并要求说明和附件。
- 金额规则：店铺保证金、营销推广保证金可直接填写主表付款金额；合同保证金和招投标保证金优先使用付款信息区金额合计回写主表付款金额。

保证金退回申请单字段：

- 主表区：核算主体、保证金类型、凭证号、说明、退回金额合计值。
- 保证金明细：行号、保证金明细关联台账、投放平台、投放账户、三方账户、店铺、保证金余额、申请退回金额、剩余金额、退回金额更新台账。
- 关键规则：保证金类型按原设计限制为店铺保证金、营销推广保证金；关联台账弹窗过滤保证金类型=当前单据保证金类型、核算主体=当前单据核算主体；同一单据内同一台账不可重复选择；申请退回金额不能大于保证金余额；剩余金额=保证金余额-申请退回金额；退回金额合计值=申请退回金额合计。

保证金台账字段：

- 通用列：单据编号、单据名称、申请日期、核算主体、保证金类型、付款方式、保证金总额、已退回金额、保证金余额、预计退回日期/预计退回时间、是否已全部退回。
- 非平台类列：合同编号、供应商、客户。
- 平台类列：三方账户、店铺、投放平台、投放账户。
- 建议补齐：占用金额、可退回金额、来源付款单号、最近退回单号、付款状态、到账状态、同步状态、最近同步时间、失败原因、组织机构、说明。

## Mock 数据建议

建议按以下数据集组织，所有数据使用本地 mock 或前端状态，不接真实第三方系统：

- `depositPaymentApplications`：保证金付款申请单 8-12 条，覆盖店铺保证金、合同保证金、付招投标保证金、退招投标保证金、营销推广保证金，状态包含草稿、审批中、已驳回、付款中、付款成功、付款失败。
- `depositReturnApplications`：保证金退回申请单 8-12 条，覆盖部分退回、全额退回、审批中、已驳回、待财务确认到账、已完成。
- `depositLedger`：保证金台账 12-20 条，平台类和非平台类各占一半，包含未退回、部分退回、退回中、已全部退回、付款失败待处理。
- `contractOptions`：合同 mock 8-12 条，包含合同编号、合同名称、供应商、客户、合同金额、合同状态。
- `storeOptions`：店铺 mock 8-12 条，包含店铺名称、平台、三方账户、主体、店铺状态。
- `adAccountOptions`：投放账户 mock 8-12 条，包含投放平台、投放账户、账户状态、所属主体。
- `paymentRecords`：模拟付款记录，包含付款申请号、支付方式、付款状态、实际支付日期、失败原因。
- `receiptRecords`：模拟退回到账记录，包含退回单号、到账日期、收款凭证号、到账状态。

样例数据要能串起来：

- 一条店铺保证金付款成功后进入台账，再做部分退回，台账余额减少但未关闭。
- 一条营销推广保证金全额退回后，台账显示是否已全部退回=是。
- 一条合同保证金生成非平台类台账，展示合同编号、供应商、客户。
- 一条付款失败记录，展示失败原因和“模拟重试付款”入口。
- 一条退回申请审批驳回，释放提交时占用的退回金额。

## 关键交互

- 列表页统一支持查询、重置、分页、导出模拟、详情抽屉。
- 付款申请单支持保存草稿、提交审批、撤回、审批通过、审批驳回、模拟付款成功、模拟付款失败。
- 保证金类型切换时动态显示字段，并清空不适用字段，避免店铺字段和投放账户字段混用。
- 选择关联合同时自动带出合同编号、供应商、客户；Demo 中合同来源为 mock 合同结构化数据。
- 选择投放平台后，投放账户下拉只展示同平台账户；选择三方账户后，店铺下拉只展示该账户关联店铺。
- 付款信息区支持新增/删除明细，金额合计自动回写主表付款金额；店铺保证金和营销推广保证金可简化为主表单笔付款。
- 提交付款申请时校验：核算主体、保证金类型、适用类型字段、付款金额或付款明细必填；金额必须大于 0。
- 审批通过后模拟生成付款记录；付款成功时写入凭证号和付款状态，并生成或更新保证金台账；付款失败时保留单据并展示失败原因，可重试。
- 台账页可按原设计区分“非平台类保证金台账”和“平台类保证金台账”，也可用页签切换，筛选项分别突出合同编号/保证金类型和店铺/保证金类型。
- 从台账行内点击“发起退回”，自动带出核算主体、保证金类型和保证金明细。
- 退回申请关联台账弹窗标题建议为“保证金信息”，显示投放账号、投放平台、三方账户、店铺、保证金总额、已消耗/已退回金额、保证金余额。
- 退回申请提交审批时，台账占用金额增加，避免重复退回同一余额；审批驳回或撤回时释放占用金额。
- 退回申请审批通过后进入“待财务确认到账”；点击“模拟确认到账”后生成收款凭证，台账已退回金额增加、占用金额减少、保证金余额减少。
- 台账详情展示来源付款单、退回申请记录、付款记录、到账记录、审批记录和金额流水，便于演示闭环。

## 第三方系统处理方式

- OA 审批、采购系统、合同结构化、OMS 资金账单解析、ERP/金蝶凭证、银行付款、CBS 支付、电商平台保证金账单全部 mock。
- 保留外部动作按钮，但只更新前端状态和操作记录：
  - “模拟提交 OA”：单据状态变为审批中，生成审批节点。
  - “模拟审批通过/驳回”：切换审批状态，记录审批人、审批日期和意见。
  - “模拟付款成功”：付款状态变为付款成功，写入实际付款日期和付款凭证号。
  - “模拟付款失败”：付款状态变为付款失败，展示失败原因和重试入口。
  - “模拟确认到账”：退回申请状态变为已到账，生成收款凭证号。
  - “模拟生成凭证”：回写凭证号、同步状态和最近同步时间。
  - “模拟资金账单解析”：从内置 mock 资金账单生成店铺保证金记录，不读取真实账单。
- 所有外部同步字段建议保留：来源系统、同步状态、最近同步时间、同步批次号、失败原因。
- 不读取真实合同，不上传真实附件，不连接真实 OA、采购系统、OMS、ERP、银行、CBS 或电商平台。

## UI/UX 重点

- 整体是财务单据和保证金台账页面，信息密度适中，突出金额、余额、状态和关联对象。
- 单据页用分组区块：申请信息、保证金信息、付款信息/保证金明细、附件模拟、审批信息、操作记录。
- 保证金类型是核心字段，建议靠前展示；不同类型字段动态切换时保持布局稳定，不让表单跳动过大。
- 金额展示统一右对齐、千分位格式；保证金余额、申请退回金额、剩余金额要在退回单中形成清晰对照。
- 状态色明确：草稿为默认，审批中/付款中/退回中为处理中，付款成功/已到账/已完成为成功，驳回/付款失败/同步失败为失败，预计退回日期逾期为警示。
- 台账页以页签或分组展示平台类/非平台类，列表列较多时支持横向滚动；关键列建议固定：单据编号、保证金类型、保证金余额、是否已全部退回、操作。
- 关联台账弹窗支持多选、已选提示和重复选择拦截；余额不足或已全部退回的记录置灰不可选。
- 附件和付款链接只做模拟展示；上传入口可保留，但不要做真实文件解析。

## 验收标准

- 页面名称、核心字段、表单分区、关联台账弹窗和台账列与原始详细设计保持一致。
- 至少跑通“保证金付款申请 -> 审批/付款 -> 保证金台账生成 -> 退回申请 -> 台账余额更新/关闭”闭环。
- 付款申请单可保存、提交、审批通过、审批驳回、模拟付款成功和付款失败。
- 退回申请单可选择保证金台账记录，支持多选且同单不可重复选择，申请退回金额不能超过保证金余额。
- 退回申请提交后能体现占用金额；审批驳回释放占用；确认到账后已退回金额、保证金余额和是否已全部退回发生变化。
- 台账可按平台类/非平台类查询、重置、查看详情、导出模拟，并能从台账发起退回。
- 表单有基础必填和金额校验，付款金额、申请退回金额必须大于 0。
- 外部系统行为全部为 mock，不发生真实 OA、采购系统、OMS、ERP、银行、CBS、电商平台或附件上传调用。
- 核心页面具备 normal、loading、empty、error 或失败提示状态。
- UI 风格统一、稳定，适合现场演示。
- 开发完成后执行项目约定检查，优先 `npm run build`；如无法执行，记录原因。
