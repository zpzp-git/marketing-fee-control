# 营销费控系统 Demo 全局 UI/UX 设计规范

## 1. 整体设计目标

本规范旨在为营销费控系统的 15 个模块提供统一的视觉语言和交互标准，确保 Mock Demo 在演示过程中表现出专业、稳重且现代的 B 端 SaaS 特质。

- **专业性**：符合财务与营销业务人员的操作习惯，强调数据的准确性与逻辑性。
- **一致性**：跨模块的组件、布局和交互逻辑高度统一，降低学习与演示成本。
- **清晰性**：通过合理的视觉层级、间距与排版，确保在演示时关键信息（状态、金额、单号）一目了然。
- **技术栈支持**：完全基于 Next.js + React + TypeScript + Tailwind CSS，不引入多余组件库。

## 2. 信息架构与导航规范

### 2.1 导航结构
- **侧边一级导航**：宽度 200px (展开) / 64px (折叠)。包含系统核心模块分类。
- **顶部面包屑**：展示当前路径，如 `预算管理 / 年度预算编制 / 详情`。
- **顶部标题区**：位于页面左上角，展示页面名称。右侧放置全局操作按钮（如“新增”、“导出”）。

### 2.2 菜单分组
参考《整体规划》中的一级导航分类，侧边栏应按以下顺序排列：
1. 工作台 (Overview)
2. 基础数据 (Base Data)
3. 预算管理 (Budget)
4. 营销计划与事项 (Plan & Matter)
5. 合同与 PO (Contract & PO)
6. 费用申请与资金 (Payment & Fund)
7. 发票与核销 (Invoice & Verification)
8. 费用预估 (Estimation)
9. 对账结算 (Settlement)
10. 财务处理 (Finance)

## 3. 页面布局规范

采用经典的上下/左右结构，确保在主流 1920x1080 分辨率下拥有最佳信息密度。

- **容器间距**：全局使用 `p-6` (24px) 边距。
- **区块卡片**：使用白色背景 `bg-white`，圆角 `rounded-lg`，极简阴影 `shadow-sm`。
- **区块间距**：垂直方向使用 `space-y-4` (16px)。
- **背景色**：系统全局背景使用浅灰色 `bg-slate-50` (or `bg-gray-50`)。

## 4. 列表页规范

列表页是演示的核心，必须具备极佳的扫描性。

- **标准结构**：标题区 -> 筛选区 -> 列表操作栏（导出/批量操作） -> 数据表格 -> 分页。
- **操作按钮位置**：
  - 全局操作（如“新建申请”）放在页面右上角。
  - 行内操作（如“查看”、“编辑”、“审批”）放在表格最右侧。

## 5. 筛选区规范

- **单行模式**：常用筛选（如单号、状态、日期）默认展示（最多 3-4 个）。
- **折叠/展开**：超过 4 个筛选项时，提供“更多筛选”按钮进行切换。
- **交互动作**：
  - 点击“查询”：表格进入 loading 状态。
  - 点击“重置”：清空所有筛选项并触发一次查询。
- **高度建议**：单行高度 48px，展开高度按需。

## 6. 表格规范

- **表头风格**：浅背景色 `bg-slate-50`，文本加粗 `font-semibold`。
- **单元格对齐**：
  - 文本类：左对齐。
  - 数值/金额：右对齐（使用等宽字体）。
  - 日期/状态：居中或左对齐。
- **行高**：标准行高 48px，数据密集型可设为 40px。
- **溢出处理**：超过列宽显示 `...`，鼠标悬停显示 Tooltip（模拟效果）。
- **空数据**：表格单元格无数据时显示 `-` 而非留空。

## 7. 表单规范

- **分组区块**：长表单必须分区块展示（如：基础信息、业务明细、审批信息）。
- **布局方式**：
  - 单列：适合详情展示或窄表单。
  - 双列/三列：适合标准表单录入，使用 `grid-cols-2` 或 `grid-cols-3`。
- **标签位置**：Label 位于 Input 上方，`text-slate-500 text-sm`。
- **必填标识**：必填项在 Label 前显示红色星号 `*`。
- **校验反馈**：输入错误时 Input 边框变红，并在下方显示 `text-red-500` 的提示文本。

## 8. 详情页 / 抽屉规范

- **摘要卡片 (Header Card)**：顶部展示单据的核心信息（单号、金额、状态、申请人），背景色区分于内容区。
- **信息分栏**：通常采用三列布局展示只读字段。
- **侧边抽屉 (Drawer)**：
  - 宽度：推荐 600px - 800px。
  - 用途：快速查看明细或简单的行级编辑，不打断主流程。
  - 标题区：包含标题、状态和右上角关闭按钮。

## 9. 弹窗规范

- **尺寸规范**：
  - 小 (sm): 400px (简单提示/确认)。
  - 中 (md): 600px (标准录入)。
  - 大 (lg): 900px (复杂明细)。
- **操作布局**：底部右侧对齐，操作顺序为 [取消] [确定]。
- **蒙层**：使用 `bg-black/50` 蒙层，点击蒙层默认不关闭（防止误触丢失表单）。

## 10. 按钮层级规范

- **Primary (主按钮)**：`bg-blue-600 text-white`。用于“提交”、“确定”、“新建”。每个页面原则上只出现一个。
- **Secondary (次按钮)**：`border border-slate-300 text-slate-700`。用于“取消”、“重置”、“保存草稿”。
- **Danger (危险操作)**：`bg-red-600 text-white`。用于“作废”、“删除”。
- **Text (文本按钮)**：`text-blue-600 hover:underline`。用于表格行内“查看详情”。

## 11. 状态标签规范

使用特定的 Tailwind 语义颜色，确保视觉语义明确：

| 状态类型 | 颜色配置 (Tailwind) | 示例 |
|---|---|---|
| **待处理/草稿** | `bg-slate-100 text-slate-600` | 草稿、未同步、待提交 |
| **处理中** | `bg-blue-50 text-blue-600 border-blue-200` | 审批中、同步中、支付中 |
| **成功/完成** | `bg-green-50 text-green-600 border-green-200` | 审批通过、同步成功、已入账 |
| **驳回/警告** | `bg-orange-50 text-orange-600 border-orange-200` | 已驳回、部分核销、存在差异 |
| **错误/失效** | `bg-red-50 text-red-600 border-red-200` | 同步失败、已作废、坏账 |

## 12. 字段展示规范

- **金额字段**：
  - 格式：保留两位小数，每三位加逗号，例如 `1,234,567.00`。
  - 对齐：表格中靠右对齐。
  - 单位：在标题或摘要区注明币种（默认 CNY）。
- **日期时间**：
  - 统一格式：`YYYY-MM-DD` (日期) 或 `YYYY-MM-DD HH:mm:ss` (时间)。
- **来源系统**：
  - 标识规范：展示为 `[系统名]` 前缀或专门标签，如 `[ERP]`、`[OA]`、`[广告平台]`。
- **单号**：
  - 可点击链接：蓝色文本，支持点击跳转至该单据详情。

## 13. State 状态规范 (Demo 演示重点)

- **Normal (常规)**：展示 Mock 数据，确保视觉平衡。
- **Loading (加载)**：
  - 局部加载：表格上方覆盖半透明遮罩并显示 Spinner。
  - 提交加载：按钮置灰并显示加载图标，防止连击。
- **Empty (空状态)**：
  - 在表格中央展示插画图标、提示语及“新建”按钮（如果有权限）。
- **Error (异常)**：
  - 同步失败必须展示失败原因（如：`接口超时 [504]`）。
  - 在详情页顶部以 Alert 组件形式展示关键错误提示。

## 14. 第三方系统 Mock 展示规范

- **同步状态栏**：对于集成 ERP/OA 的单据，在标题下方展示“同步状态：同步成功 / 2026-05-06 10:00”。
- **重试操作**：当 Mock 状态为“同步失败”时，提供“重新同步”按钮。
- **外部单号**：展示第三方系统的原始单号（如 ERP 凭证号），点击可跳转（Mock 弹出“已模拟跳转至 ERP 详情”提示）。

## 15. 响应式与信息密度建议

- **侧边栏自动折叠**：屏幕宽度小于 1280px 时自动折叠侧边栏为图标模式。
- **信息密度**：
  - 核心字段（金额、状态）使用较粗字重 (`font-medium`)。
  - 次要说明信息使用较浅颜色 (`text-slate-400`) 和较小字号 (`text-xs`)。

## 16. Codex 实现注意事项

- **组件复用**：不要为每个页面写重复的 Table 和 Form，封装成基础组件。
- **Tailwind 标准**：严格使用 Tailwind 预定义数值，不要写内联样式（如 `style={{width: '243px'}}`）。
- **TypeScript 定义**：所有 Mock 数据结构必须有对应的 `interface` 定义。
- **演示状态流转**：
  - 利用 `useState` 模拟状态变化（如点击“发起审批”后，状态瞬间从“草稿”变为“审批中”）。
  - 利用 `setTimeout` 模拟同步加载过程（建议 500ms - 1000ms），增强真实感。
