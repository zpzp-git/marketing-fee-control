# 3.7.13 付款管理 - UI/UX 补充说明

本说明旨在指导“付款管理”模块的 UI/UX 实现，确保其符合全局设计规范，并突出“申请 -> 审批 -> 模拟支付 -> 凭证回写”的演示闭环。

## 1. 模块 UI 目标
- **支付进度全景化**：清晰展示从应付确认到最终银行回单的完整路径。
- **异常处理便捷化**：突出退票重付、充值差异等异常场景的交互。
- **台账联动实时化**：展示付款后应付余额与投放账户余额的即时变动。

## 2. 页面清单
- **工作台**：付款管理工作台（仪表盘）。
- **台账类**：供应商应付账款台账、供应商预付款台账、投放账户余额台账、投放账户明细台账。
- **表单类**：对公付款申请单、对公预付款申请单、投放账户充值/退款申请单、退票重付单。

## 3. 页面布局重点
- **付款工作台**：采用 Dashboard 布局，顶部展示 4-5 个关键指标卡片。
- **付款单表单**：核心是“付款信息”区块（包含账号、支付方式）。对于“投放充值”，重点展示财务的“实际付款”录入区。
- **联动选择**：在发起付款时，弹窗选择应付记录需支持“批量选择”。

## 4. 列表页字段与表格列建议
### 4.1 供应商应付账款台账
- **主要表格列**：供应商、核算主体、应付金额、已付款金额、应付余额、单据状态、操作。
- **高亮建议**：应付余额 > 0 的记录，金额加粗显示。

### 4.2 投放账户余额台账
- **主要表格列**：投放平台、投放账户、充值余额、预充值总额、现金余额、操作。

## 5. 新增 / 编辑 / 详情展示方式
- **场景切换**：对公付款单根据“是否有合同/是否核销”动态展示结算明细或营销事项明细。
- **支付预览**：在提交付款前，展示一个“付款凭条预览”（Mock），包含付款方与收款方信息。
- **差异标注**：在投放充值确认页，如果充值金额与实付金额不符，自动出现橙色“充值差异”标记。

## 6. 核心操作按钮与反馈
- **模拟支付**：财务审批后的按钮，点击后显示“支付指令已发送至银行...”，随后变为“支付成功”。
- **发起重付**：在支付失败详情页，醒目展示“发起退票重付”主按钮。
- **导出凭证**：支付完成后，提供“下载付款回单”按钮（弹出 mock 图片）。

## 7. 状态标签与状态流转展示
- **待付款 / 未同步**：`bg-slate-100 text-slate-600`
- **支付中 / 核销中**：`bg-blue-50 text-blue-600 border-blue-200`
- **支付成功 / 已完成**：`bg-green-50 text-green-600 border-green-200`
- **支付失败 / 存在差异**：`bg-red-50 text-red-600 border-red-200`

## 8. 第三方系统 mock 展示方式
- **CBS 状态同步**：详情页展示“招行 CBS 已受理，流水号：CBS-XXXX”。
- **银行回单模拟**：点击回单按钮，展示一个设计精美的模态框，模仿银行回单样式。
- **投放平台余额更新**：充值成功后，账户余额数字执行一个上升的数值滚动效果。

## 9. normal / loading / empty / error 状态补充
- **Error**：支付失败后，在单据顶部展示红色 Alert，说明失败原因（如：`收款账号银行代码错误`）。
- **Loading**：支付过程中，主操作按钮显示 Loading 状态并文字更新为“处理中”。

## 10. Codex 实现注意事项
- **余额计算逻辑**：实现付款金额扣减应付余额、增加已付金额的原子操作。
- **差异计算**：投放充值中实时计算 `实际支付 - 申请充值` 的差额。
- **多账号模拟**：准备一组 mock 供应商银行账号数据，支持自动填入。
