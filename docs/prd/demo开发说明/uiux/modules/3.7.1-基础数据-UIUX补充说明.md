# 3.7.1 基础数据 - UI/UX 补充说明

本说明旨在指导“基础数据”模块的 UI/UX 实现，确保其符合全局设计规范，并突出“申请 -> 审批 -> 台账更新”的演示闭环。

## 1. 模块 UI 目标
- **数据结构化**：以清晰的层级展示费用类型、营销活动和账户信息。
- **流转透明化**：通过状态标签和审批记录，清晰展示主数据的生效过程。
- **关联直观化**：在选择预算科目或费用小类时，提供便捷的弹窗/下拉体验。

## 2. 页面清单
- **台账类**：费用类型台账、营销活动与费用关系台账、投放账户台账、三方账户台账。
- **表单类**：新增/调整费用类型、营销活动管理/变更、投放账户申请/变更/注销、三方账户申请/变更/关闭、预算科目申请。

## 3. 页面布局重点
- **台账页**：标题栏靠右放置“新增申请”主按钮。筛选区采用单行折叠模式。表格使用固定表头，金额和状态列右/中对齐。
- **表单页**：采用双列布局。顶部展示“申请信息”区块（只读），中间为“业务信息”区块（录入），底部为“审批信息”（模拟）及操作栏。
- **详情抽屉**：用于从台账快速查看详情。右侧弹出，宽度 600px。

## 4. 列表页字段与表格列建议
### 4.1 费用类型台账
- **筛选区字段**：费用名称（搜索）、费用大类（下拉）、状态（标签组）、所属部门。
- **主要表格列**：费用编号、费用名称、费用类型、费用大类、核算科目、发票类目、状态、更新时间、操作（详情/变更）。

### 4.2 营销活动与费用关系台账
- **筛选区字段**：活动名称、渠道、店铺、预算科目、状态。
- **主要表格列**：活动名称、类型、渠道、店铺、预算科目、费用小类、核算科目、状态、操作。

## 5. 新增 / 编辑 / 详情展示方式
- **动态表单**：在“新增费用类型”中，根据“申请类型”切换字段。切换时使用平滑的渐隐渐现效果。
- **只读详情**：在“详情”模式下，所有 Input 变为文本展示，背景去掉边框，保持对齐。
- **台账引用**：在“变更”表单中，顶部显示“原记录”对比卡片，下方显示“变更后”录入区。

## 6. 核心操作按钮与反馈
- **提交审批**：主按钮，点击后进入“审批中”状态，弹出“单据已提交，请等待审批”Toast。
- **模拟审批通过**：演示专用按钮，点击后台账实时插入/更新数据，并跳转回台账页。
- **保存草稿**：次按钮，点击后保持在当前页，Toast 提示“已保存至草稿”。

## 7. 状态标签与状态流转展示
使用全局规范中的语义色：
- **已启用 / 审批通过**：`bg-green-50 text-green-600 border-green-200`
- **审批中 / 同步中**：`bg-blue-50 text-blue-600 border-blue-200`
- **待生效 / 待确认**：`bg-orange-50 text-orange-600 border-orange-200`
- **已禁用 / 已注销**：`bg-slate-100 text-slate-600`
- **已驳回 / 同步失败**：`bg-red-50 text-red-600 border-red-200`

## 8. 第三方系统 mock 展示方式
- **OA 审批模拟**：在详情页底部展示“审批流预览”，包含“申请人 -> 财务 BP -> 财务主管”节点。
- **同步状态栏**：对于投放账户，在标题下方展示：`[来源：外部系统] 同步状态：同步成功 | 最近更新：2026-05-06 10:00`。
- **同步重试**：同步失败时，在失败原因旁提供“模拟重试同步”蓝色文本链接。

## 9. normal / loading / empty / error 状态补充
- **Loading**：列表加载时使用 Skeleton 骨架屏；提交时按钮进入 Loading 态并禁用。
- **Empty**：查询无结果展示插画 + “暂无匹配数据” + “重置筛选”按钮。
- **Error**：表单校验错误在 Input 下方即时提示；同步失败在详情页顶部 Alert 提示。

## 10. Codex 实现注意事项
- **State 驱动**：利用全局 Context 或页面级 `useState` 模拟 Mock 数据的增删改查。
- **交互延时**：所有异步操作增加 500ms 模拟延时，使演示看起来更稳重。
- **字段对齐**：金额字段必须使用等宽字体并右对齐。
