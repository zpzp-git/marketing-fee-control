# 3.7.15 其他损益 - UI/UX 补充说明

本说明旨在指导“其他损益”模块的 UI/UX 实现，确保其符合全局设计规范，并突出“多样化损益确认 -> 预提计提 -> 冲销”的闭环。

## 1. 模块 UI 目标
- **业务场景分类化**：针对会员积分、预计退货、渠道折扣等不同场景提供适配的表单结构。
- **计算逻辑可视化**：在表单中直接展示计算公式（如：`收入 * 退货率`），提高演示的可理解性。
- **账务处理闭环化**：清晰展示从损益确认到凭证生成，再到台账冲销的完整链路。

## 2. 页面清单
- **工作台**：其他损益工作台。
- **台账类**：其他损益台账、其他损益预提台账、内部交易信息台账、店铺收入台账、预计退货率台账。
- **表单类**：其他损益确认单、会员积分预提单、预计退货预提单、渠道折扣计提单、内部交易结算单、物流费用结算单、冲销弹窗。

## 3. 页面布局重点
- **损益确认单**：采用标准的“财务凭证式”布局，包含借贷方明细表，并实时计算借贷平衡。
- **预提类表单**：顶部展示“测算依据”（如积分余额、月度收入），下方展示“预提结果”表格。
- **工作台**：突出“待处理”事项，使用快捷统计卡片引导至不同类型的损益确认。

## 4. 列表页字段与表格列建议
### 4.1 其他损益预提台账
- **主要表格列**：预提月份、业务类型、核算主体、预提金额、预提凭证号、状态、冲销状态、操作。
- **业务类型标签**：使用不同颜色的边框或背景区分：`积分`、`退货`、`折扣`、`物流`。

## 5. 新增 / 编辑 / 详情展示方式
- **计算引导**：在输入“GMV”和“计提比例”时，右侧自动浮现计算过程。
- **借贷平衡**：在其他损益确认单底部，实时比对借贷合计，不平衡时“提交”按钮置灰。
- **预提追溯**：在预提台账详情中，提供“查看冲销记录”入口，展示冲销凭证。

## 6. 核心操作按钮与反馈
- **模拟同步数据**：在预提单顶部，点击“同步最新业务数据”后，表格明细自动载入。
- **发起冲销**：台账行内操作，点击后弹出红色调的冲销确认框。
- **确认入账**：内部交易结算单特有操作，点击后更新状态并生成入账凭证号。

## 7. 状态标签与状态流转展示
- **未预提 / 未入账**：`bg-slate-100 text-slate-600`
- **审批中 / 冲销中**：`bg-blue-50 text-blue-600 border-blue-200`
- **已预提 / 已入账**：`bg-green-50 text-green-600 border-green-200`
- **已冲销 / 冲销失败**：`bg-red-50 text-red-600 border-red-200`

## 8. 第三方系统 mock 展示方式
- **来源系统图标**：在列表项旁展示微型图标标识来源：`[ECRP]`、`[OMS]`、`[有赞]`。
- **自动计算提示**：在“预计退货金额”单元格旁展示 `自动计算` 的蓝色提示标签。
- **凭证号链接**：凭证号点击后弹出“模拟凭证详情”抽屉，展示分录。

## 9. normal / loading / empty / error 状态补充
- **Error**：同步失败时，展示“来源系统异常 [503]”，并在行内提供“重试”按钮。
- **Empty**：查询无结果时，针对不同场景（如：`无待计提返利`）提供特定文案。

## 10. Codex 实现注意事项
- **计算函数**：实现会员积分、预计退货、渠道折扣的同步计算 JS 逻辑。
- **借贷校验**：在提交前执行 `totalDebit === totalCredit` 的强校验。
- **状态联动**：内部交易入账后，确保来源明细台账的“是否入账”同步更新。
